# 2.2. Бинарный поиск по ответу

## Главная идея

Бинарный поиск умеет искать не только элемент в массиве. Он может искать **минимальное или максимальное число, для которого выполняется условие**.

Нужен монотонный ответ:

```text
False False False False True True True True
```

Если для некоторого значения условие стало истинным и дальше всегда остаётся истинным, можно найти первый `True` бинарным поиском.

Или наоборот:

```text
True True True True False False False
```

Тогда можно искать последний `True`.

Этот приём называют **бинарным поиском по ответу**.

## Универсальная схема минимального подходящего ответа

```python
def first_true(left, right, predicate):
    """Ищет первое значение в [left, right), где predicate == True."""
    while left < right:
        middle = left + (right - left) // 2

        if predicate(middle):
            right = middle
        else:
            left = middle + 1

    return left
```

Перед применением нужно ответить на три вопроса:

1. Что является предполагаемым ответом `middle`?
2. Как быстро проверить, подходит ли `middle`?
3. Почему результаты проверки монотонны?

## Задача 1. Целый квадратный корень

Нужно найти наибольшее целое `x`, для которого:

```text
x² <= number
```

Например:

- `9 -> 3`;
- `21 -> 4`, потому что `4² <= 21`, а `5² > 21`.

Предикат `x² <= number` монотонен:

```text
для number = 21

x:       0  1  2  3  4  5  6 ...
x²<=21:  T  T  T  T  T  F  F ...
```

Ищем последний `True`.

```python
def integer_sqrt(number):
    if number < 0:
        raise ValueError("square root is undefined for negatives")

    left = 0
    right = number
    answer = 0

    while left <= right:
        middle = left + (right - left) // 2
        square = middle * middle

        if square <= number:
            answer = middle
            left = middle + 1
        else:
            right = middle - 1

    return answer
```

Сложность:

- время — `O(log number)`;
- дополнительная память — `O(1)`.

В Python для рабочего кода существует точная стандартная функция:

```python
from math import isqrt

isqrt(21)  # 4
```

Задача нужна не ради собственной замены `isqrt`, а ради тренировки поиска границы.

## Задача 2. Дипломы на квадратной доске

Есть `n` прямоугольников размера `width × height`. Их нельзя поворачивать. Нужно найти минимальную сторону квадратной доски, на которой они поместятся без наложения в виде сетки.

Для предполагаемой стороны `side`:

```python
columns = side // width
rows = side // height
fits = columns * rows >= n
```

Если дипломы помещаются на доске со стороной `side`, они поместятся и на любой большей доске. Получаем монотонность:

```text
малые стороны: False
достаточно большая сторона и все следующие: True
```

```python
def minimum_board_side(width, height, count):
    if width <= 0 or height <= 0 or count <= 0:
        raise ValueError("all arguments must be positive")

    left = 0
    right = max(width, height) * count

    while left < right:
        middle = left + (right - left) // 2
        fits = (middle // width) * (middle // height) >= count

        if fits:
            right = middle
        else:
            left = middle + 1

    return left
```

### Почему правая граница точно подходит

`max(width, height) * count` позволяет выложить все прямоугольники в один ряд или столбец внутри квадрата. Эта граница может быть неэффективно большой, но она гарантированно допустима.

### Почему нельзя использовать площадь как единственную проверку

Условие:

```text
side² >= width * height * count
```

не гарантирует размещение по сетке. Общей площади может хватать, но размеры прямоугольников не позволят разложить их по сторонам. Нужно считать целые количество строк и столбцов.

Сложность — `O(log(max(width, height) * count))`, потому что проверка одного `middle` выполняется за `O(1)`.

## Задача 3. Два ксерокса

Есть один исходный лист и два ксерокса. Первый делает копию за `x` минут, второй — за `y`. Нужно получить всего `n` копий за минимальное время.

Сначала доступен только один лист, поэтому сначала работает более быстрый ксерокс:

```python
first_copy_time = min(x, y)
```

После первой копии есть два листа, и оба ксерокса могут работать параллельно. Остаётся изготовить `n - 1` копий.

За `time` минут два аппарата сделают:

```python
time // x + time // y
```

копий.

```python
def minimum_copy_time(copies, first_speed, second_speed):
    if copies <= 0:
        return 0
    if first_speed <= 0 or second_speed <= 0:
        raise ValueError("copy time must be positive")
    if copies == 1:
        return min(first_speed, second_speed)

    first_copy = min(first_speed, second_speed)
    remaining = copies - 1

    left = 0
    right = remaining * min(first_speed, second_speed)

    while left < right:
        middle = left + (right - left) // 2
        produced = middle // first_speed + middle // second_speed

        if produced >= remaining:
            right = middle
        else:
            left = middle + 1

    return first_copy + left
```

Если в конкретном условии `n` означает общее число листов вместе с оригиналом, а не количество новых копий, формула изменится. В олимпиадных задачах важно читать определение `n` буквально.

## Как придумывать границы

### Левая граница

Значение, которое точно слишком мало или является минимально возможным. Часто это `0`.

### Правая граница

Значение, которое точно подходит, даже если оно далеко от оптимального.

Если верхнюю границу трудно вывести, её иногда находят экспоненциальным расширением:

```python
right = 1

while not predicate(right):
    right *= 2
```

После этого ответ гарантированно лежит между предыдущей и новой границами.

## Как доказать монотонность

Для задачи про доску:

```text
если всё помещается при side = 100,
то при side = 101 места не станет меньше.
```

Для ксероксов:

```text
если за 20 минут можно сделать нужное количество,
то за 21 минуту результат не ухудшится.
```

Если подобное утверждение неверно, обычный бинарный поиск по ответу применять нельзя.

## Частые ошибки

1. Искать бинарно, не доказав монотонность.
2. Выбрать правую границу, которая не гарантирует допустимый ответ.
3. Перепутать первый подходящий ответ с последним неподходящим.
4. Получить бесконечный цикл из-за границ, которые не уменьшаются.
5. Ошибиться на `n - 1` в задаче с первым листом.
6. Использовать вещественное деление вместо целочисленного `//`.

## Что важно запомнить

1. Бинарный поиск работает по любому монотонному пространству ответов, не только по массиву.
2. Нужно написать функцию-проверку `predicate(answer)`.
3. Для поиска минимума обычно ищут первый `True`.
4. Для поиска максимума — последний `True` или первую ложную границу.
5. Корректные начальные границы и инвариант важнее запоминания конкретного кода.
