# 1.5. Связные списки

## Самая важная оговорка для Python-разработчика

В этой лекции слово **«список» означает связный список** (`linked list`). Это не то же самое, что встроенный Python `list`.

- Python `list` — динамический массив ссылок.
- Связный список — цепочка отдельных узлов, соединённых ссылками.

В JavaScript встроенный `Array` тоже не является связным списком. Готового универсального `LinkedList` в стандартном языке нет: его либо реализуют самостоятельно, либо используют специализированную библиотеку.

## Идея односвязного списка

Каждый элемент называется **узлом** (`node`) и хранит две вещи:

1. полезные данные — `data`;
2. ссылку на следующий узел — `next`.

```text
head
  |
  v
[10 | next] -> [20 | next] -> [30 | None]
```

- `head` — ссылка на первый узел;
- `tail` — ссылка на последний узел, если мы решили её хранить;
- последний узел ссылается на `None`;
- узлы не обязаны находиться рядом в памяти.

Простейший узел на Python:

```python
class Node:
    def __init__(self, data, next_node=None):
        self.data = data
        self.next = next_node
```

Обрати внимание: `next` здесь — ссылка на другой объект `Node`, а не индекс массива.

## Чем связный список отличается от массива

### Динамический массив

```text
[A] [B] [C] [D]
```

- внутренние ячейки расположены подряд;
- по индексу можно обратиться за `O(1)`;
- вставка в начало требует сдвинуть остальные элементы — `O(n)`;
- последовательное расположение хорошо использует кеш процессора.

### Связный список

```text
[A | *]     [B | *]     [C | None]
     --------^  ---------^
```

- узлы могут находиться в разных местах памяти;
- чтобы добраться до элемента с индексом 100, нужно пройти предыдущие 100 узлов — `O(n)`;
- вставка после уже известного узла меняет несколько ссылок — `O(1)`;
- каждый узел расходует дополнительную память на ссылки;
- разрозненные узлы хуже используют кеш процессора.

## Почему узлы не обязаны лежать рядом

Новый узел создаётся там, где менеджер памяти нашёл место. Предыдущий узел хранит ссылку, по которой можно найти следующий.

Это даёт гибкость: не требуется искать один большой непрерывный блок памяти. Но за гибкость мы платим дополнительными ссылками и более медленным обходом на современном железе.

Поэтому утверждение «вставка в связный список быстрее массива» верно только при определённых условиях: место вставки уже известно. Если его сначала приходится искать, общий результат будет `O(n)`.

## Учебная реализация односвязного списка

```python
class Node:
    def __init__(self, data, next_node=None):
        self.data = data
        self.next = next_node


class LinkedList:
    def __init__(self):
        self.head = None
        self.tail = None
        self.size = 0

    def prepend(self, data):
        node = Node(data, self.head)
        self.head = node

        if self.tail is None:
            self.tail = node

        self.size += 1

    def append(self, data):
        node = Node(data)

        if self.tail is None:
            self.head = node
            self.tail = node
        else:
            self.tail.next = node
            self.tail = node

        self.size += 1

    def find(self, target):
        current = self.head

        while current is not None:
            if current.data == target:
                return current
            current = current.next

        return None
```

Это учебный код. В обычном Python-проекте самостоятельно писать общий связный список требуется редко.

## Вставка в начало: O(1)

Было:

```text
head -> [10] -> [20] -> None
```

Создаём новый узел и направляем его `next` на прежнюю голову:

```text
head -> [5] -> [10] -> [20] -> None
```

Независимо от длины списка меняется фиксированное число ссылок.

```python
def prepend(head, value):
    return Node(value, head)
```

## Вставка в конец

Если хранится `tail`, операция занимает `O(1)`:

```python
new_node = Node(value)
linked_list.tail.next = new_node
linked_list.tail = new_node
```

Если `tail` не хранится, сначала нужно пройти от `head` до последнего узла. Тогда операция занимает `O(n)`.

`tail` — хороший пример обмена памяти на скорость: храним ещё одну ссылку и ускоряем частую операцию.

## Вставка после известного узла

```python
def insert_after(node, value):
    if node is None:
        raise ValueError("node must not be None")

    node.next = Node(value, node.next)
```

Если `node` уже передан функции, вставка имеет `O(1)`.

Если передан не узел, а значение, например «вставить после числа 20», узел сначала нужно найти. Поиск занимает `O(n)`, поэтому вся операция тоже `O(n)`.

## Поиск и доступ по позиции: O(n)

У связного списка нет формулы для прямого вычисления адреса элемента. Начинаем с головы и переходим по `next`:

```python
def get_at(head, index):
    current = head

    for _ in range(index):
        if current is None:
            raise IndexError("index out of range")
        current = current.next

    if current is None:
        raise IndexError("index out of range")

    return current.data
```

Встроенный Python `list` здесь заметно удобнее: `items[index]` работает за `O(1)`.

## Удаление узла

В односвязном списке для удаления обычно нужен предыдущий узел:

```text
[A] -> [B] -> [C]
        удалить B

[A] ----------> [C]
```

Нужно записать:

```python
previous.next = current.next
```

Само переключение ссылки — `O(1)`. Но поиск `current` и `previous` от головы обычно занимает `O(n)`.

## Таблица сложностей

| Операция | Связный список | Python `list` |
|---|---:|---:|
| Получить элемент по индексу | `O(n)` | `O(1)` |
| Найти значение | `O(n)` | `O(n)` |
| Вставить в начало | `O(1)` | `O(n)` |
| Добавить в конец при наличии `tail` | `O(1)` | амортизированно `O(1)` |
| Вставить после уже известного узла | `O(1)` | `O(n)` из-за сдвига |
| Удалить после уже известного узла | `O(1)` | `O(n)` из-за сдвига |

Таблица не означает, что связный список всегда лучше для вставок. В реальной задаче часто сначала нужно найти нужное место, а это `O(n)`.

## Двусвязный список

В двусвязном списке узел хранит ссылки в обе стороны:

```text
None <- [A] <-> [B] <-> [C] -> None
```

```python
class DoublyNode:
    def __init__(self, data):
        self.data = data
        self.prev = None
        self.next = None
```

Плюсы:

- можно двигаться вперёд и назад;
- известный узел можно удалить за `O(1)`;
- удобно реализовывать дек и LRU-кеш.

Минусы:

- дополнительная ссылка `prev` в каждом узле;
- при вставке и удалении нужно правильно обновить больше связей;
- больше способов получить ошибку.

## Разворот односвязного списка

Нужно поменять направление всех ссылок:

```text
A -> B -> C -> None

None <- A <- B <- C
                  ^
                new head
```

Алгоритм использует три ссылки:

- `previous` — уже развёрнутая часть;
- `current` — узел, который обрабатываем;
- `next_node` — сохранённый следующий узел.

```python
def reverse_linked_list(head):
    previous = None
    current = head

    while current is not None:
        next_node = current.next
        current.next = previous
        previous = current
        current = next_node

    return previous
```

Почему нужно сначала сохранить `next_node`: после `current.next = previous` старая ссылка на продолжение списка будет потеряна.

- время — `O(n)`;
- дополнительная память — `O(1)`.

## Цикл в связном списке

В ошибочном или специальном списке последний узел может ссылаться не на `None`, а на один из предыдущих узлов:

```text
A -> B -> C -> D
          ^      |
          |______|
```

Обычный цикл `while current is not None` здесь никогда не закончится.

### Простое решение через множество

```python
def has_cycle_with_set(head):
    visited = set()
    current = head

    while current is not None:
        if current in visited:
            return True
        visited.add(current)
        current = current.next

    return False
```

- время — `O(n)`;
- дополнительная память — `O(n)`.

### Алгоритм Флойда: медленный и быстрый указатели

```python
def has_cycle(head):
    slow = head
    fast = head

    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next

        if slow is fast:
            return True

    return False
```

`slow` проходит один узел за шаг, `fast` — два. Если цикла нет, быстрый указатель достигнет `None`. Если цикл есть, быстрый указатель рано или поздно догонит медленный внутри кольца.

- время — `O(n)`;
- дополнительная память — `O(1)`.

Здесь сравниваются сами узлы через `is`, а не их значения. Два разных узла могут хранить одинаковые данные.

## Поиск середины списка

Снова используем быстрый и медленный указатели:

```python
def middle_node(head):
    slow = head
    fast = head

    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next

    return slow
```

Когда `fast` дошёл до конца, `slow` прошёл примерно половину пути.

- время — `O(n)`;
- дополнительная память — `O(1)`;
- список обходится один раз.

Для чётного количества узлов такая реализация возвращает второй из двух центральных узлов. Это не ошибка, а выбранное правило. В условии реальной задачи его нужно уточнять.

## Где связные списки встречаются на практике

Связный список редко нужен как замена обычному Python `list`, но его идеи используются в:

- двусторонних очередях;
- LRU-кешах: словарь даёт быстрый поиск, двусвязный список — быстрый перенос и удаление;
- внутренних структурах планировщиков;
- списках свободных блоков в менеджерах памяти;
- некоторых реализациях хеш-таблиц;
- истории переходов и цепочках операций;
- ядрах ОС и низкоуровневом коде.

## Когда выбирать что

В Python по умолчанию:

- нужен порядок, перебор и доступ по индексу — `list`;
- нужны добавление и удаление с обоих концов — `collections.deque`;
- нужен быстрый поиск по ключу — `dict`;
- нужен учебный опыт или особая структура с известными узлами — собственный связный список.

Не выбирай связный список только потому, что у него вставка `O(1)`. Сначала спроси: «У меня уже есть ссылка на место вставки или его ещё нужно искать?»

## Что важно запомнить

1. Python `list` — динамический массив, а не связный список.
2. Связный список состоит из отдельных узлов и ссылок между ними.
3. Доступ по индексу и поиск занимают `O(n)`.
4. Вставка после уже известного узла занимает `O(1)`.
5. `tail` превращает добавление в конец из `O(n)` в `O(1)`.
6. Медленный и быстрый указатели помогают найти цикл или середину за `O(n)` времени и `O(1)` памяти.
