# Самопроверка к занятию 4.4

## Вопросы

1. Какую проблему обычного BST решает красно-чёрное дерево?
2. Что такое `NIL`-лист?
3. Может ли обычный узел без потомков быть красным?
4. Почему два красных узла не могут идти подряд?
5. Что называется чёрной высотой?
6. Почему новый узел вставляется красным?
7. Что происходит при красных родителе и дяде?
8. Что сохраняет поворот дерева?
9. Какова худшая сложность поиска и вставки?

## Проверь свойства

Можно ли считать корректным такое дерево?

```text
        10(B)
       /     \
     5(R)    15(R)
```

Если все отсутствующие дети представлены чёрными `NIL`, дерево корректно:

- корень чёрный;
- у красных узлов чёрные `NIL`-дети;
- каждый путь от корня к `NIL` содержит одинаковое число чёрных узлов.

## Найди нарушение

```text
        10(B)
       /
     5(R)
     /
   3(R)
```

Красный `5` имеет красного ребёнка `3`. Требуется перекрашивание или поворот в зависимости от цвета дяди и окружающей структуры.

## Практика 1. Проверка корня

```python
tree = RedBlackTree()

for key in [10, 20, 30]:
    tree.insert(key)

assert tree.root.color == BLACK
assert tree.inorder() == [10, 20, 30]
assert validate_red_black_tree(tree)
```

После вставки `30` потребуется левый поворот, и корнем станет `20`.

## Практика 2. Случай с красным дядей

Последовательность:

```python
[10, 5, 15, 1]
```

Перед восстановлением после вставки `1`:

- родитель `5` красный;
- дядя `15` красный;
- дед `10` чёрный.

Родитель и дядя перекрашиваются в чёрный, дед — в красный, а затем корень снова становится чёрным.

## Практика 3. Массовая проверка

```python
tree = RedBlackTree()

for key in range(1000):
    assert tree.insert(key)
    assert validate_red_black_tree(tree)

assert tree.inorder() == list(range(1000))
```

Даже последовательная вставка отсортированных ключей не должна превратить красно-чёрное дерево в линейную цепочку.

## Ответы

1. Не допускает линейной высоты и гарантирует логарифмические основные операции.
2. Общий специальный чёрный узел, представляющий отсутствие ребёнка.
3. Да. Обязательное правило чёрного цвета относится к `NIL`, а не ко всем узлам без обычных потомков.
4. Это отдельный инвариант, ограничивающий максимальную длину путей и не позволяющий накопить слишком много красных узлов.
5. Количество чёрных узлов на нисходящем пути до `NIL` согласно выбранному соглашению; оно одинаково для всех таких путей.
6. Красный узел не увеличивает чёрную высоту путей.
7. Родитель и дядя становятся чёрными, дед — красным, после чего проверка продолжается от деда.
8. Порядок ключей бинарного дерева поиска.
9. `O(log n)`.
