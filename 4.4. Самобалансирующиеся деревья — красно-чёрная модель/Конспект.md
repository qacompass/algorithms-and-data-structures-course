# 4.4. Красно-чёрные деревья: как BST сохраняет высоту

## Проблема обычного BST

Бинарное дерево поиска быстро работает только при небольшой высоте.

Если вставлять значения в неудачном порядке:

```python
[1, 2, 3, 4, 5]
```

обычное BST может выродиться:

```text
1
 \
  2
   \
    3
     \
      4
       \
        5
```

Высота становится `O(n)`, а поиск, вставка и удаление — `O(n)`.

Самобалансирующееся дерево после изменений перестраивает небольшую часть структуры, чтобы высота оставалась `O(log n)`.

## Что такое красно-чёрное дерево

Красно-чёрное дерево — бинарное дерево поиска, в котором каждый узел имеет дополнительный цвет:

- красный;
- чёрный.

Цвет не описывает данные. Это один бит служебной информации, помогающий контролировать форму дерева.

Строгого равенства высот слева и справа не требуется. Баланс поддерживается через несколько инвариантов.

## NIL-листья

В теории отсутствующие дети представлены специальными чёрными узлами `NIL`:

```text
       10(B)
       /   \
    NIL(B) NIL(B)
```

Именно `NIL`, а не любой обычный узел без детей, обязательно является чёрным.

Обычный узел-лист с данными может быть красным:

```text
       10(B)
       /
     5(R)
    /   \
 NIL   NIL
```

Это важное различие между бытовым словом «лист» и формальным sentinel-узлом в красно-чёрном дереве.

## Пять основных свойств

1. Каждый узел красный или чёрный.
2. Корень чёрный.
3. Все `NIL`-листья чёрные.
4. У красного узла нет красных детей — два красных узла не идут подряд.
5. Любой путь от выбранного узла до его descendant `NIL` содержит одинаковое число чёрных узлов.

Последнее число называется **чёрной высотой**.

Иногда свойства нумеруют иначе или объединяют, но смысл остаётся тем же.

## Чёрная высота

Чёрная высота узла — количество чёрных узлов на пути от него к `NIL` согласно выбранному соглашению. Сам начальный узел обычно не учитывают, а конечный `NIL` учитывают.

Важно не запомнить формулировку дословно, а понять ограничение:

```text
все нисходящие пути содержат одинаковое количество чёрных опорных узлов
```

Из-за запрета двух красных подряд один путь не может быть больше другого более чем примерно в два раза.

## Почему высота логарифмическая

Путь может чередовать цвета:

```text
black -> red -> black -> red -> black
```

Красных узлов не больше, чем чёрных. Поэтому обычная высота не превосходит примерно удвоенную чёрную высоту.

Поддерево с чёрной высотой `b` содержит не меньше `2^b - 1` внутренних узлов. Отсюда получается граница:

```text
h <= 2 * log2(n + 1)
```

Следовательно, поиск, вставка, удаление, минимум и максимум имеют `O(log n)` даже в худшем случае.

## Сравнение с AVL-деревом

AVL-дерево требует, чтобы высоты дочерних поддеревьев каждого узла отличались не более чем на 1.

Красно-чёрное дерево допускает более свободную форму, но всё равно гарантирует логарифмическую высоту.

Упрощённо:

- AVL балансируется строже и может давать меньшую высоту;
- красно-чёрное дерево часто выполняет меньше перестроений при обновлениях;
- обе структуры гарантируют `O(log n)` основных операций;
- фактический выбор зависит от реализации и профиля нагрузки.

## Как восстанавливается баланс

Используются две операции:

1. **перекрашивание** узлов;
2. **поворот** небольшой части дерева.

Поворот меняет структуру, но сохраняет порядок BST.

# Повороты

## Левый поворот

До:

```text
      X
     / \
    A   Y
       / \
      B   C
```

После левого поворота вокруг `X`:

```text
        Y
       / \
      X   C
     / \
    A   B
```

Порядок ключей сохраняется:

```text
A < X < B < Y < C
```

## Правый поворот

Это зеркальная операция:

```text
        Y              X
       / \            / \
      X   C    ->     A   Y
     / \                / \
    A   B              B   C
```

Поворот работает за `O(1)`: меняется фиксированное количество ссылок.

## Зачем нужна ссылка parent

Во время восстановления после вставки алгоритм обращается к:

- родителю;
- деду;
- дяде — второму ребёнку деда.

Ссылка `parent` упрощает подъём вверх и повороты.

## Структура узла

```python
RED = True
BLACK = False


class RBNode:
    def __init__(self, key=None, color=RED):
        self.key = key
        self.color = color
        self.left = None
        self.right = None
        self.parent = None
```

В полноценной реализации все отсутствующие дети будут ссылаться на один общий чёрный sentinel `NIL`.

# Вставка

## Почему новый узел сначала красный

Обычная BST-вставка добавляет узел вместо `NIL`.

Если новый узел сделать чёрным, каждый путь через него получит дополнительный чёрный узел и сразу нарушит равенство чёрной высоты.

Красный узел чёрную высоту не меняет. Возможна только одна новая проблема: его родитель тоже красный.

## Базовый случай

Если родитель чёрный, все свойства уже соблюдены. Ничего исправлять не требуется.

## Красный родитель и красный дядя

```text
        G(B)
       /    \
    P(R)    U(R)
    /
  X(R)
```

Перекрашиваем:

```text
        G(R)
       /    \
    P(B)    U(B)
    /
  X(R)
```

Теперь нарушение могло подняться к `G`, если его родитель тоже красный. Продолжаем проверку вверх.

## Красный родитель и чёрный дядя: линия

```text
        G(B)
       /
    P(R)
    /
  X(R)
```

Выполняем правый поворот вокруг `G` и меняем цвета `P` и `G`:

```text
       P(B)
      /   \
    X(R)  G(R)
```

Для правой стороны действия зеркальны: левый поворот.

## Красный родитель и чёрный дядя: угол

```text
        G(B)
       /
    P(R)
       \
       X(R)
```

Сначала левым поворотом вокруг `P` превращаем угол в линию, затем применяем предыдущий случай с правым поворотом вокруг `G`.

Для зеркальной конфигурации повороты меняются местами.

## Финальное правило

После восстановления корень всегда принудительно окрашивается в чёрный.

# Учебная реализация вставки

Ниже реализованы:

- поиск места как в BST;
- вставка уникального ключа;
- левый и правый повороты;
- восстановление цветов и структуры;
- поиск и inorder-обход.

Удаление красно-чёрного узла заметно сложнее и здесь не включено.

```python
RED = True
BLACK = False


class RBNode:
    def __init__(self, key=None, color=RED):
        self.key = key
        self.color = color
        self.left = None
        self.right = None
        self.parent = None


class RedBlackTree:
    def __init__(self):
        self.nil = RBNode(color=BLACK)
        self.nil.left = self.nil
        self.nil.right = self.nil
        self.nil.parent = self.nil
        self.root = self.nil

    def contains(self, key):
        current = self.root

        while current is not self.nil:
            if key == current.key:
                return True

            if key < current.key:
                current = current.left
            else:
                current = current.right

        return False

    def insert(self, key):
        parent = self.nil
        current = self.root

        while current is not self.nil:
            parent = current

            if key < current.key:
                current = current.left
            elif key > current.key:
                current = current.right
            else:
                return False

        node = RBNode(key=key, color=RED)
        node.left = self.nil
        node.right = self.nil
        node.parent = parent

        if parent is self.nil:
            self.root = node
        elif key < parent.key:
            parent.left = node
        else:
            parent.right = node

        self._fix_insert(node)
        return True

    def _left_rotate(self, node):
        pivot = node.right
        node.right = pivot.left

        if pivot.left is not self.nil:
            pivot.left.parent = node

        pivot.parent = node.parent

        if node.parent is self.nil:
            self.root = pivot
        elif node is node.parent.left:
            node.parent.left = pivot
        else:
            node.parent.right = pivot

        pivot.left = node
        node.parent = pivot

    def _right_rotate(self, node):
        pivot = node.left
        node.left = pivot.right

        if pivot.right is not self.nil:
            pivot.right.parent = node

        pivot.parent = node.parent

        if node.parent is self.nil:
            self.root = pivot
        elif node is node.parent.right:
            node.parent.right = pivot
        else:
            node.parent.left = pivot

        pivot.right = node
        node.parent = pivot

    def _fix_insert(self, node):
        while node.parent.color == RED:
            grandparent = node.parent.parent

            if node.parent is grandparent.left:
                uncle = grandparent.right

                if uncle.color == RED:
                    node.parent.color = BLACK
                    uncle.color = BLACK
                    grandparent.color = RED
                    node = grandparent
                else:
                    if node is node.parent.right:
                        node = node.parent
                        self._left_rotate(node)

                    node.parent.color = BLACK
                    node.parent.parent.color = RED
                    self._right_rotate(node.parent.parent)
            else:
                uncle = grandparent.left

                if uncle.color == RED:
                    node.parent.color = BLACK
                    uncle.color = BLACK
                    grandparent.color = RED
                    node = grandparent
                else:
                    if node is node.parent.left:
                        node = node.parent
                        self._right_rotate(node)

                    node.parent.color = BLACK
                    node.parent.parent.color = RED
                    self._left_rotate(node.parent.parent)

        self.root.color = BLACK
        self.root.parent = self.nil

    def inorder(self):
        result = []

        def walk(node):
            if node is self.nil:
                return

            walk(node.left)
            result.append(node.key)
            walk(node.right)

        walk(self.root)
        return result
```

Использование:

```python
tree = RedBlackTree()

for key in [33, 21, 27, 15, 40, 50, 10]:
    tree.insert(key)

print(tree.inorder())
# [10, 15, 21, 27, 33, 40, 50]
```

## Как проверить инварианты

Тестировать только отсортированный inorder недостаточно: обычное несбалансированное BST тоже его пройдёт.

Нужно проверять:

- корень чёрный;
- красный узел не имеет красных детей;
- левая часть меньше ключа, правая больше;
- чёрная высота всех путей одинакова;
- родительские ссылки корректны.

```python
def validate_red_black_tree(tree):
    if tree.root is tree.nil:
        return True

    if tree.root.color != BLACK:
        return False

    def visit(node, lower=None, upper=None):
        if node is tree.nil:
            return 1

        if lower is not None and node.key <= lower:
            raise ValueError("BST lower bound violated")

        if upper is not None and node.key >= upper:
            raise ValueError("BST upper bound violated")

        if node.color == RED:
            if node.left.color == RED or node.right.color == RED:
                raise ValueError("red node has a red child")

        if node.left is not tree.nil and node.left.parent is not node:
            raise ValueError("invalid left parent link")

        if node.right is not tree.nil and node.right.parent is not node:
            raise ValueError("invalid right parent link")

        left_height = visit(node.left, lower, node.key)
        right_height = visit(node.right, node.key, upper)

        if left_height != right_height:
            raise ValueError("black heights differ")

        return left_height + (1 if node.color == BLACK else 0)

    try:
        visit(tree.root)
    except ValueError:
        return False

    return True
```

## Сложность восстановления после вставки

Поиск места занимает `O(log n)`, потому что высота ограничена.

При восстановлении:

- перекрашивание может подниматься до корня;
- повороты работают за `O(1)` каждый;
- весь путь вверх имеет длину `O(log n)`.

Итоговая вставка — `O(log n)`.

## Удаление в общих чертах

Сначала узел удаляется по правилам BST. Затем может возникнуть недостаток чёрного узла на одном из путей — условное состояние «двойной чёрный».

Исправление анализирует:

- цвет брата;
- цвета ближнего и дальнего племянников;
- положение удалённого узла;
- необходимость перекрашивания и поворотов.

Алгоритм симметричен для левой и правой стороны, но содержит больше случаев, чем вставка. Его сложность остаётся `O(log n)`.

Для прикладного проекта самописная реализация такой структуры обычно не нужна: лучше использовать проверенную библиотечную коллекцию.

## Где используются упорядоченные самобалансирующиеся деревья

- ассоциативные контейнеры с упорядоченными ключами;
- множества с поиском соседних значений;
- диапазонные запросы;
- планирование и системные структуры;
- индексы и внутренние структуры программ;
- задачи, где одновременно нужны поиск, вставка и отсортированный обход.

Конкретная библиотека может использовать красно-чёрное дерево, AVL, B-дерево или другую структуру. Название интерфейса `map` само по себе не гарантирует конкретную реализацию.

## Python и красно-чёрные деревья

Встроенный `dict` — хеш-таблица, а не красно-чёрное дерево. Он не предоставляет поиск ближайшего ключа или диапазона по упорядочению.

В стандартной библиотеке нет прямого аналога универсального `TreeMap`. В зависимости от задачи используют:

- `dict` / `set` для точного поиска;
- `list` + `bisect` для небольших упорядоченных коллекций;
- `heapq` для приоритетного края;
- индекс базы данных;
- специализированную проверенную коллекцию.

## Частые ошибки

1. Считать любой обычный узел-лист обязательно чёрным — чёрными являются sentinel `NIL`.
2. Путать красно-чёрный баланс с требованием AVL `|balance| <= 1`.
3. Считать дерево идеально полным или идеально симметричным.
4. Выполнить поворот и забыть обновить `parent` или корень.
5. Вставить новый узел чёрным и нарушить чёрную высоту.
6. При красном дяде делать поворот вместо перекрашивания.
7. Обработать только левую конфигурацию и забыть зеркальную правую.
8. Проверять только inorder, не проверяя цветовые инварианты.
9. Использовать учебную реализацию в критичном приложении без исчерпывающих тестов.

## Что важно запомнить

1. Красно-чёрное дерево — BST с цветовым инвариантом и гарантированной высотой `O(log n)`.
2. `NIL`-листья чёрные; обычный узел без детей может быть красным.
3. Красный узел не может иметь красного родителя или ребёнка.
4. Все пути к `NIL` содержат одинаковое количество чёрных узлов.
5. Повороты сохраняют порядок BST и работают за `O(1)`.
6. Новый узел вставляется красным, затем дерево восстанавливается перекрашиванием и поворотами.
7. Основные операции гарантированно работают за `O(log n)`.
