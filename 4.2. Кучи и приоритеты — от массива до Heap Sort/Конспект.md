# 4.2. Кучи и приоритеты: от массива до Heap Sort

## Какую проблему решает куча

Иногда не нужен полный порядок всех элементов. Нужно только быстро отвечать на вопрос:

```text
"Какой элемент сейчас имеет наивысший приоритет?"
```

Примеры:

- следующая задача планировщика;
- самый срочный запрос;
- минимальная стоимость маршрута;
- несколько крупнейших или наименьших значений;
- ближайшее событие по времени;
- лучший кандидат из динамически меняющегося набора.

Если каждый раз искать максимум в обычном неотсортированном списке, потребуется `O(n)`. Куча поддерживает доступ к приоритетному элементу за `O(1)`, а вставку и извлечение — за `O(log n)`.

## Что такое двоичная куча

Двоичная куча — почти полное бинарное дерево с правилом приоритета.

### Почти полное дерево

- все уровни, кроме последнего, заполнены полностью;
- последний уровень заполняется слева направо.

Благодаря форме высота всегда `O(log n)`.

### Max-heap

Значение родителя не меньше значений его детей:

```text
parent >= left_child
parent >= right_child
```

Максимум находится в корне.

```text
          21
        /    \
      19      18
     /  \    / \
   11   16  15  10
```

### Min-heap

Родитель не больше детей:

```text
parent <= children
```

Минимум находится в корне.

## Куча не является отсортированным деревом

В max-heap известно только, что родитель не меньше непосредственных потомков и, следовательно, всех узлов ниже по цепочке.

Между левым и правым поддеревьями общего порядка нет:

```text
          100
        /     \
      20       90
```

`20` слева меньше `90` справа — это совершенно нормально.

Поэтому:

- максимум находится быстро;
- поиск произвольного значения в общем случае остаётся `O(n)`;
- inorder-обход кучи не даёт отсортированную последовательность;
- куча и BST решают разные задачи.

## Представление дерева в массиве

Почти полная форма позволяет не хранить ссылки `left`, `right` и `parent`.

```text
дерево:               массив:

        21             [21, 19, 18, 11, 16, 15, 10]
      /    \
    19      18
   /  \    / \
 11   16  15  10
```

Для индекса `i` при нумерации с нуля:

```python
parent = (i - 1) // 2
left = 2 * i + 1
right = 2 * i + 2
```

Корень всегда находится на индексе `0`.

## Почему в массиве нет дырок

Последний уровень заполняется слева направо. Значит, узлы в порядке уровней занимают последовательные индексы.

Если разрешить произвольные пропуски, формулы потомков будут приводить к пустым ячейкам и компактное представление исчезнет.

## Просеивание вниз

`sift_down` восстанавливает max-heap, когда значение узла может быть меньше одного из детей.

1. Находим крупнейшего из узла и его детей.
2. Если крупнейший — сам узел, всё готово.
3. Иначе меняем узел с крупнейшим ребёнком.
4. Продолжаем с новой позиции.

```python
def sift_down(heap, index, size=None):
    if size is None:
        size = len(heap)

    while True:
        largest = index
        left = 2 * index + 1
        right = 2 * index + 2

        if left < size and heap[left] > heap[largest]:
            largest = left

        if right < size and heap[right] > heap[largest]:
            largest = right

        if largest == index:
            return

        heap[index], heap[largest] = heap[largest], heap[index]
        index = largest
```

Почему меняемся с **большим** ребёнком: если поставить наверх меньшего, больший ребёнок всё ещё нарушит правило max-heap.

Максимальный путь равен высоте дерева, поэтому `sift_down` занимает `O(log n)`.

## Построение кучи снизу

Листья уже являются корректными кучами из одного элемента. Начинаем с последнего узла, у которого есть дети:

```python
last_parent = len(data) // 2 - 1
```

и идём к корню:

```python
def build_max_heap(data):
    heap = list(data)

    for index in range(len(heap) // 2 - 1, -1, -1):
        sift_down(heap, index)

    return heap
```

## Почему heapify имеет O(n), а не O(n log n)

Грубая оценка говорит:

```text
n узлов * O(log n) = O(n log n)
```

Это корректная верхняя граница, но не точная: большинство узлов не проходят всю высоту.

- примерно половина узлов — листья, их стоимость `0`;
- примерно четверть находится на высоте `1`;
- примерно восьмая часть — на высоте `2`;
- дорогих узлов около корня очень мало.

Сумма выглядит примерно так:

```text
n/4 * 1 + n/8 * 2 + n/16 * 3 + ... = O(n)
```

Поэтому построение кучи снизу через `heapify` занимает `O(n)`.

Последовательная вставка всех `n` элементов действительно имела бы `O(n log n)` в худшем случае.

## Просеивание вверх

После вставки новый элемент добавляется в конец массива, чтобы сохранить почти полную форму. Если он больше родителя, поднимаем его.

```python
def sift_up(heap, index):
    while index > 0:
        parent = (index - 1) // 2

        if heap[parent] >= heap[index]:
            return

        heap[parent], heap[index] = heap[index], heap[parent]
        index = parent
```

## Вставка в max-heap

```python
def max_heap_push(heap, value):
    heap.append(value)
    sift_up(heap, len(heap) - 1)
```

- добавление в конец — амортизированно `O(1)`;
- подъём — `O(log n)`;
- общая сложность — `O(log n)`.

## Просмотр максимума

```python
def max_heap_peek(heap):
    if not heap:
        raise IndexError("peek from empty heap")

    return heap[0]
```

Сложность — `O(1)`.

## Извлечение максимума

Нельзя просто удалить корень: в массиве появилась бы дырка и нарушилась форма дерева.

Алгоритм:

1. меняем корень с последним элементом;
2. удаляем бывший корень с конца массива;
3. просеиваем новый корень вниз.

```python
def max_heap_pop(heap):
    if not heap:
        raise IndexError("pop from empty heap")

    heap[0], heap[-1] = heap[-1], heap[0]
    maximum = heap.pop()

    if heap:
        sift_down(heap, 0)

    return maximum
```

Сложность — `O(log n)`.

## Сводка операций

| Операция | Сложность |
|---|---:|
| Посмотреть корень | `O(1)` |
| Вставить | `O(log n)` |
| Извлечь корень | `O(log n)` |
| Построить кучу снизу | `O(n)` |
| Найти произвольное значение | `O(n)` |

# Очередь с приоритетом

Обычная FIFO-очередь возвращает самый старый элемент. Очередь с приоритетом возвращает элемент с лучшим приоритетом.

```text
задача A: приоритет 5
задача B: приоритет 1
задача C: приоритет 3
```

Порядок обработки зависит от соглашения:

- меньшее число важнее;
- или большее число важнее.

Куча — распространённая реализация очереди с приоритетом.

## Python heapq — min-heap

Стандартный модуль Python хранит минимум в `heap[0]`.

```python
import heapq

heap = []

heapq.heappush(heap, 5)
heapq.heappush(heap, 1)
heapq.heappush(heap, 3)

minimum = heap[0]       # 1, O(1)
value = heapq.heappop(heap)  # 1, O(log n)
```

Печатать внутренний список как «отсортированный результат» нельзя:

```python
print(heap)
```

Он удовлетворяет свойствам кучи, но не обязан быть полностью отсортирован.

## Преобразование списка в кучу

```python
import heapq

numbers = [12, 11, 13, 5, 6, 7]
heapq.heapify(numbers)
```

`heapify()` изменяет список на месте и занимает `O(n)`.

## Max-heap через отрицательные значения

С классическим `heapq` max-heap часто моделируют отрицательными приоритетами:

```python
import heapq

max_heap = []

for value in [5, 1, 9, 3]:
    heapq.heappush(max_heap, -value)

maximum = -heapq.heappop(max_heap)  # 9
```

Для объектов обычно кладут кортеж `(-priority, item)`.

## Равные приоритеты и несравнимые объекты

```python
import heapq
from itertools import count

queue = []
order = count()

heapq.heappush(queue, (2, next(order), {"task": "report"}))
heapq.heappush(queue, (1, next(order), {"task": "alert"}))
heapq.heappush(queue, (2, next(order), {"task": "backup"}))

priority, _, task = heapq.heappop(queue)
```

Поля кортежа сравниваются по очереди:

1. приоритет;
2. уникальный порядковый номер;
3. объект уже сравнивать не потребуется.

Счётчик также делает порядок задач с одинаковым приоритетом предсказуемым.

## Где используется очередь с приоритетом

- алгоритм Дейкстры;
- поиск A*;
- планировщики;
- симуляции событий;
- распределение задач;
- слияние нескольких отсортированных потоков;
- поиск `k` лучших элементов.

# Пирамидальная сортировка

Heap Sort использует max-heap для сортировки по возрастанию.

1. Превращаем массив в max-heap.
2. Максимум находится на позиции `0`.
3. Меняем его с последним элементом неотсортированной части.
4. Уменьшаем размер кучи.
5. Просеиваем новый корень вниз.
6. Повторяем.

Справа постепенно растёт отсортированная часть.

## Реализация Heap Sort

```python
def heap_sort(items):
    size = len(items)

    # O(n): строим max-heap на месте.
    for index in range(size // 2 - 1, -1, -1):
        sift_down(items, index, size)

    # Переносим текущий максимум вправо.
    for end in range(size - 1, 0, -1):
        items[0], items[end] = items[end], items[0]
        sift_down(items, 0, end)

    return items
```

В `sift_down(items, 0, end)` параметр `end` является размером активной кучи и не включается в неё. Элементы справа уже находятся на окончательных местах.

## Сложность Heap Sort

- построение кучи — `O(n)`;
- `n - 1` извлечений/просеиваний — `O(n log n)`;
- итоговое время — `O(n log n)` в лучшем, среднем и худшем случаях;
- дополнительная память — `O(1)` для in-place реализации;
- алгоритм неустойчив.

Неустойчивость означает, что элементы с одинаковым ключом могут поменять взаимный порядок.

После завершения получен отсортированный массив. То, что возрастающий массив одновременно удовлетворяет свойству min-heap, не означает, что Heap Sort «превратил max-heap в рабочую min-heap»: целью алгоритма является сортировка, а не дальнейшее использование структуры как очереди с приоритетом.

## Heap Sort против других сортировок

### Преимущества

- гарантированное `O(n log n)`;
- сортировка на месте;
- нет риска квадратичной деградации как у неудачного Quick Sort;
- не требуется `O(n)` дополнительной памяти как у простой Merge Sort.

### Недостатки

- неустойчива;
- на практике часто хуже использует кеш, чем хорошо реализованный Quick Sort;
- библиотечная сортировка Python обычно предпочтительнее;
- сложнее вставок или пузырька для понимания и реализации.

## Поиск k наименьших элементов

Если нужно только несколько элементов, сортировать весь массив необязательно.

```python
import heapq

smallest = heapq.nsmallest(3, numbers)
largest = heapq.nlargest(3, numbers)
```

Для маленького `k` относительно `n` это может быть выгоднее полной сортировки.

## Потоковый поиск k крупнейших

Поддерживаем min-heap размера `k`. Корень — наименьший среди текущих лидеров.

```python
import heapq


def k_largest(stream, k):
    if k <= 0:
        return []

    leaders = []

    for value in stream:
        if len(leaders) < k:
            heapq.heappush(leaders, value)
        elif value > leaders[0]:
            heapq.heapreplace(leaders, value)

    return sorted(leaders, reverse=True)
```

- память — `O(k)`;
- время — `O(n log k)`;
- не нужно хранить весь поток.

## Частые ошибки

1. Считать внутренний массив кучи полностью отсортированным.
2. Путать кучу с бинарным деревом поиска.
3. Искать произвольный элемент в куче за `O(log n)` — такой гарантии нет.
4. При `sift_down` меняться не с самым приоритетным ребёнком.
5. После удаления корня нарушить почти полную форму дерева.
6. Называть нижнее построение кучи `O(n log n)` вместо точного `O(n)`.
7. Забыть, что Python `heapq` реализует min-heap.
8. Положить в кучу кортежи с равными приоритетами и несравнимыми объектами без счётчика.
9. Считать Heap Sort устойчивой.

## Что важно запомнить

1. Куча гарантирует порядок между родителем и детьми, а не между всеми элементами.
2. Почти полная форма позволяет хранить дерево в обычном массиве.
3. Корень доступен за `O(1)`, вставка и извлечение — за `O(log n)`.
4. `heapify` снизу работает за `O(n)`.
5. Python `heapq` — готовая min-heap и основа очереди с приоритетом.
6. Heap Sort гарантирует `O(n log n)`, работает на месте, но неустойчива.
7. Куча особенно полезна, когда нужен не полный порядок, а лучший текущий элемент.
