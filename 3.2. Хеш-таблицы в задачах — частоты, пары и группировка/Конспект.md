# 3.2. Практические задачи с хеш-таблицами

## Зачем нужен этот урок

Знать устройство `dict` недостаточно. Важно научиться замечать ситуации, где хеш-таблица превращает повторные поиски в быстрые обращения по ключу.

В задачах этого занятия словарь используется четырьмя способами:

1. как счётчик частот;
2. как память о ранее встреченных значениях;
3. как индекс значения по его идентификатору;
4. как контейнер для группировки элементов по общему признаку.

Отдельная задача с животными показывает другое: иногда хеш-таблица вообще не нужна, а правильным инструментом становятся сортировка и жадный алгоритм.

## Паттерн 1. Счётчик частот

Пусть дана последовательность:

```python
letters = "banana"
```

Словарь частот выглядит так:

```python
{
    "b": 1,
    "a": 3,
    "n": 2,
}
```

Универсальная реализация:

```python
def frequencies(items):
    counts = {}

    for item in items:
        counts[item] = counts.get(item, 0) + 1

    return counts
```

В Python также существует готовый класс:

```python
from collections import Counter

counts = Counter("banana")
```

- построение счётчика — в среднем `O(n)`;
- дополнительная память — `O(k)`, где `k` — количество различных значений.

## Задача 1. Найти добавленную букву

Строка `changed` получена из `original` перестановкой символов и добавлением одной буквы. Нужно вернуть добавленный символ.

```text
original = "uio"
changed  = "oeiu"
ответ    = "e"
```

Порядок символов изменён, поэтому сравнивать позиции бесполезно. Важны только количества каждого символа.

### Решение со счётчиком

```python
from collections import Counter


def extra_character(original, changed):
    difference = Counter(changed) - Counter(original)

    for character, count in difference.items():
        if count > 0:
            return character

    return ""
```

`Counter` при вычитании оставляет только положительные остатки.

### Решение одним словарём

```python
def extra_character(original, changed):
    counts = {}

    for character in changed:
        counts[character] = counts.get(character, 0) + 1

    for character in original:
        counts[character] -= 1

    for character, count in counts.items():
        if count > 0:
            return character

    return ""
```

Сложность:

- время — `O(len(original) + len(changed))`;
- память — `O(k)` для различных символов.

### Важное условие задачи

Такое решение предполагает, что `changed` действительно содержит все символы `original` и не более одного дополнительного символа. Если входные данные могут быть произвольными, нужно валидировать частоты и длины.

```python
def extra_character_checked(original, changed):
    if len(changed) != len(original) + 1:
        return None

    difference = Counter(changed)
    difference.subtract(original)

    positive = [
        character
        for character, count in difference.items()
        if count == 1
    ]
    invalid = any(count < 0 or count > 1 for count in difference.values())

    if invalid or len(positive) != 1:
        return None

    return positive[0]
```

### Альтернатива через XOR

Если известно, что добавлен ровно один символ, можно применить побитовое XOR к кодам всех символов:

```python
def extra_character_xor(original, changed):
    result = 0

    for character in original + changed:
        result ^= ord(character)

    return chr(result)
```

Одинаковые значения уничтожаются, потому что `x ^ x == 0`.

- время — `O(n)`;
- дополнительная память — `O(1)`.

Счётчик универсальнее и понятнее, а XOR полезен как специальный математический приём при строгих гарантиях входа.

## Паттерн 2. Запоминание увиденных значений

Во время прохода по данным словарь или множество хранит информацию о том, что уже встречалось.

Типичный вопрос:

```text
"Видел ли я раньше значение, которое дополняет текущее до нужного ответа?"
```

## Задача 2. Два числа с заданной суммой

Дан неотсортированный список и `target`. Нужно найти индексы двух разных элементов, сумма которых равна `target`.

```python
numbers = [2, 7, 11, 15]
target = 9

# ответ: (0, 1)
```

Для текущего числа `number` нужен партнёр:

```python
missing = target - number
```

### Однопроходное решение

```python
def two_sum(numbers, target):
    seen = {}

    for index, number in enumerate(numbers):
        missing = target - number

        if missing in seen:
            return seen[missing], index

        seen[number] = index

    return None
```

Словарь содержит:

```text
значение -> индекс ранее просмотренного элемента
```

### Почему сначала ищем, а потом записываем

```python
numbers = [3]
target = 6
```

Один элемент нельзя использовать дважды. Если сначала положить `3` в словарь, а затем искать дополнение, алгоритм может ошибочно вернуть один и тот же индекс.

В однопроходном варианте словарь содержит только предыдущие элементы, поэтому индексы гарантированно различаются.

### Повторяющиеся числа

```python
numbers = [3, 3]
target = 6
```

На первом шаге `seen = {3: 0}`. На втором дополнение `3` уже найдено, и возвращаются `(0, 1)`.

### Сложность

- время — в среднем `O(n)`;
- дополнительная память — `O(n)`;
- худшее время операций словаря теоретически может быть `O(n)`, но обычная практическая оценка решения — `O(n)` в среднем.

### Сравнение с сортировкой

Можно отсортировать значения и применить два указателя за `O(n log n)`. Но если нужны исходные индексы, придётся сортировать пары `(value, original_index)`.

Словарь даёт среднее `O(n)` и сразу сохраняет индекс, поэтому обычно является естественным выбором для неотсортированного входа.

## Паттерн 3. Жадный выбор после сортировки

Не каждая задача текущего занятия решается хеш-таблицей. Иногда нужно выбрать наилучшее локальное действие, которое не мешает получить оптимальный общий результат.

## Задача 3. Накормить максимум животных

Есть потребности животных и размеры порций. Одну порцию можно отдать только одному животному. Порция подходит, если она не меньше потребности.

```python
animals = [8, 2, 3, 2]
food = [1, 4, 3, 8]
```

Нужно накормить максимальное количество животных.

### Почему наивный выбор может ошибиться

```text
animals = [1, 8]
food    = [8, 1]
```

Если отдать порцию `8` животному с потребностью `1`, животное с потребностью `8` останется голодным. Оптимально отдать `1` первому, а `8` второму.

### Жадная стратегия

1. Сортируем животных по возрастанию потребности.
2. Сортируем порции по размеру.
3. Текущую порцию пытаемся отдать самому неприхотливому ещё не накормленному животному.
4. Если порция мала, переходим к следующей порции.

```python
def maximum_fed_animals(animals, food):
    needs = sorted(animals)
    portions = sorted(food)
    animal_index = 0

    for portion in portions:
        if animal_index == len(needs):
            break

        if portion >= needs[animal_index]:
            animal_index += 1

    return animal_index
```

### Почему стратегия корректна

Если самая маленькая доступная порция может накормить самое неприхотливое животное, отдавать ему более крупную порцию нет смысла: крупная может понадобиться животному с большей потребностью.

Если порция слишком мала даже для самого неприхотливого оставшегося животного, она не подойдёт ни одному следующему — её можно пропустить.

Это жадный обменный аргумент: любой оптимальный план можно перестроить так, чтобы маленькая подходящая порция обслуживала маленькую потребность, не ухудшая результат.

### Сложность

- сортировка — `O(a log a + f log f)`;
- линейный проход — `O(a + f)`;
- общая временная сложность определяется сортировкой;
- `sorted()` создаёт копии и требует дополнительную память.

Если исходные списки можно менять, допустимо использовать `.sort()`.

## Паттерн 4. Группировка по каноническому ключу

Разные элементы могут принадлежать одной группе, если для них можно построить одинаковое нормализованное представление.

```text
исходный объект -> канонический ключ -> группа
```

## Задача 4. Сгруппировать анаграммы

Анаграммы состоят из одинаковых символов с одинаковыми количествами, но в разном порядке:

```text
"eat", "tea", "ate"
```

После сортировки символов все они дают ключ:

```text
"aet"
```

```python
def group_anagrams(words):
    groups = {}

    for word in words:
        key = "".join(sorted(word))
        groups.setdefault(key, []).append(word)

    return list(groups.values())
```

Пример:

```python
words = ["eat", "tea", "tan", "ate", "nat", "bat"]

# Один из возможных результатов:
# [["eat", "tea", "ate"], ["tan", "nat"], ["bat"]]
```

Порядок групп может не быть частью условия. В тестах лучше сравнивать содержимое групп, а не случайный порядок вывода.

### Сложность ключа через сортировку

Пусть:

- `n` — количество слов;
- `m` — средняя длина слова.

Сортировка одного слова занимает `O(m log m)`, всех слов — примерно `O(n * m log m)`.

### Ключ через частоты

Если алфавит заранее ограничен, ключом может быть кортеж количеств:

```python
def latin_lowercase_signature(word):
    counts = [0] * 26

    for character in word:
        index = ord(character) - ord("a")

        if not 0 <= index < 26:
            raise ValueError("only a-z characters are supported")

        counts[index] += 1

    return tuple(counts)


def group_latin_anagrams(words):
    groups = {}

    for word in words:
        key = latin_lowercase_signature(word)
        groups.setdefault(key, []).append(word)

    return list(groups.values())
```

Построение ключа занимает `O(m)`, но реализация привязана к конкретному алфавиту.

Для произвольного Unicode проще и надёжнее использовать отсортированную строку или аккуратно нормализованный счётчик.

## Почему список нельзя использовать как ключ Python dict

Частотный массив изменяем и поэтому не хешируется:

```python
counts = [1, 0, 2]
# groups[counts] = word  # TypeError
```

Кортеж неизменяем и подходит:

```python
key = tuple(counts)
groups[key] = [word]
```

Это практическое следствие требования стабильного хеша ключа.

## JavaScript-версии паттернов

### Частоты

```javascript
function frequencies(items) {
  const counts = new Map();

  for (const item of items) {
    counts.set(item, (counts.get(item) ?? 0) + 1);
  }

  return counts;
}
```

### Two Sum

```javascript
function twoSum(numbers, target) {
  const seen = new Map();

  for (let index = 0; index < numbers.length; index += 1) {
    const missing = target - numbers[index];

    if (seen.has(missing)) {
      return [seen.get(missing), index];
    }

    seen.set(numbers[index], index);
  }

  return null;
}
```

## Как распознать подходящую задачу

Подумай о словаре или множестве, если встречается вопрос:

- сколько раз встречалось значение;
- встречалось ли оно раньше;
- где находится объект с данным идентификатором;
- существует ли дополнение до `target`;
- какие элементы имеют одинаковый нормализованный признак;
- как избежать повторного линейного поиска.

Подумай о другом инструменте, если нужны:

- диапазоны и ближайшие значения — сортировка или дерево;
- порядок поступления — очередь;
- минимальный/максимальный приоритет — куча;
- оптимальное сопоставление ресурсов по размеру — часто сортировка и жадный проход.

## Частые ошибки

1. В `two_sum` использовать один индекс дважды.
2. Хранить только факт наличия, когда для ответа нужен индекс.
3. Забыть про повторяющиеся символы и использовать `set` вместо частот.
4. Использовать изменяемый список как ключ словаря.
5. Предполагать определённый порядок групп, если условие его не гарантирует.
6. Применять жадный алгоритм без объяснения, почему локальный выбор безопасен.
7. Забыть, что `sorted()` создаёт новый список, а `.sort()` меняет исходный.

## Что важно запомнить

1. Хеш-таблица часто хранит не исходные данные, а полезную информацию о них: частоту, индекс или группу.
2. Однопроходный `two_sum` обеспечивает разные индексы естественным образом.
3. Канонический ключ превращает сложное сравнение объектов в обычный поиск по словарю.
4. Для анаграмм ключом может быть отсортированная строка или кортеж частот.
5. Не всякая задача рядом с хеш-таблицами решается хешированием: иногда сортировка и жадный выбор лучше.
