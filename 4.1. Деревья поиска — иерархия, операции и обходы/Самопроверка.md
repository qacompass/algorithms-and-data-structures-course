## Построй дерево

Последовательно вставь:

```python
[8, 3, 10, 1, 6, 14, 4, 7, 13]
```

Получится:

```text
        8
      /   \
     3     10
    / \      \
   1   6      14
      / \    /
     4   7  13
```

## Определи обходы

Для дерева выше:

```text
inorder:   1, 3, 4, 6, 7, 8, 10, 13, 14
preorder:  8, 3, 1, 6, 4, 7, 10, 14, 13
postorder: 1, 4, 7, 6, 3, 13, 14, 10, 8
BFS:       8, 3, 10, 1, 6, 14, 4, 7, 13
```

## Практика 1. Проверить наличие

```python
def contains(root, target):
    return search(root, target) is not None
```

Почему это быстрее полного обхода только при корректном BST? Потому что правило порядка позволяет на каждом шаге отбросить целое поддерево.

## Практика 2. Высота дерева

```python
def height(root):
    if root is None:
        return -1

    return 1 + max(height(root.left), height(root.right))
```

Для листа оба пустых поддерева имеют высоту `-1`, поэтому результат равен `0`.

## Практика 3. Проверить корректность BST

```python
def is_valid_bst(root, lower=None, upper=None):
    if root is None:
        return True

    if lower is not None and root.value <= lower:
        return False

    if upper is not None and root.value >= upper:
        return False

    return (
        is_valid_bst(root.left, lower, root.value)
        and is_valid_bst(root.right, root.value, upper)
    )
```

Проверять только непосредственных детей недостаточно: элемент глубоко в левом поддереве тоже обязан быть меньше корня.

## Ответы

1. Бинарное дерево ограничивает число потомков двумя, BST дополнительно задаёт порядок ключей.
2. Максимальную длину пути от корня до листа согласно выбранному соглашению.
3. Например, при последовательной вставке уже отсортированных значений все узлы могут уйти в одну сторону.
4. Минимум — в крайнем левом узле, максимум — в крайнем правом.
5. Лист, один потомок, два потомка.
6. Inorder: `left -> node -> right`.
7. Очередь.
8. `O(n)`, потому что каждый узел нужно посетить.
