# Самопроверка к лекции 1.4

## Вопросы

1. Что происходит, когда `size == capacity` и вызывается `append`?
2. Почему отдельный `append` иногда имеет сложность `O(n)`?
3. Почему при этом для `append` указывают амортизированное `O(1)`?
4. Почему увеличение ёмкости на фиксированные 10 элементов хуже геометрического роста?
5. Почему нежелательно уменьшать массив сразу при заполнении наполовину?
6. Какова сложность слияния списков длины `n` и `m`?
7. Зачем после основного цикла слияния добавлять остаток одного из списков?

## Проследи расширение

Пусть начальная ёмкость равна 1 и при заполнении удваивается.

Добавь мысленно значения `A`, `B`, `C`, `D`, `E`. После каждого добавления запиши:

- `size`;
- `capacity`;
- потребовалось ли копирование;
- сколько старых элементов было скопировано.

Ожидаемые ёмкости:

```text
1 -> 2 -> 4 -> 8
```

## Реализуй самостоятельно

Напиши `merge_sorted(first, second)`, не используя `sorted()` и `.sort()`.

Проверь крайние случаи:

```python
merge_sorted([], [])
merge_sorted([1, 2], [])
merge_sorted([], [1, 2])
merge_sorted([1, 1], [1])
merge_sorted([-5, 10], [-2, 0, 20])
```

Ожидаемые результаты:

```python
[]
[1, 2]
[1, 2]
[1, 1, 1]
[-5, -2, 0, 10, 20]
```

## Найди проблему

```python
def collect(source):
    result = []

    for item in source:
        result = result + [item]

    return result
```

Каждая операция `+` создаёт новый список и копирует уже накопленные элементы. Для большого `source` суммарная работа может стать квадратичной.

Исправление:

```python
def collect(source):
    result = []

    for item in source:
        result.append(item)

    return result
```

## Ответы

1. Выделяется более крупный блок, старые ссылки копируются, новый элемент записывается, старый блок перестаёт использоваться.
2. При расширении приходится копировать `n` существующих элементов.
3. Дорогие расширения происходят редко, а их суммарная стоимость распределяется между множеством дешёвых вставок.
4. Расширения происходят слишком часто, и большие массивы приходится многократно копировать.
5. Добавление и удаление около границы будут постоянно вызывать расширение и сжатие.
6. `O(n + m)` по времени и `O(n + m)` памяти для нового результата.
7. Основной цикл заканчивается, как только закончился хотя бы один список. Необработанные элементы второго списка уже находятся в правильном порядке, но их всё равно нужно перенести в результат.
