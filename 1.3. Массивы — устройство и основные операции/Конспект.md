# 1.3. Массивы. Часть 1

## Главное недоразумение: массив и Python list — не совсем одно и то же

В лекции под массивом понимается **классический массив**:

- элементы одного типа;
- каждый элемент занимает одинаковое количество байтов;
- элементы лежат в памяти подряд;
- размер обычно известен заранее;
- к элементу можно быстро обратиться по индексу.

В Python мы чаще используем `list`. Это не классический массив значений, а **динамический массив ссылок на объекты**.

```python
items = [10, "hello", {"active": True}]
```

Объекты здесь имеют разные типы и размеры. Однако ячейки внутреннего массива хранят не сами эти объекты, а ссылки на них. Сами ссылки имеют одинаковый размер, поэтому Python может хранить их в массиве и быстро получать по индексу.

Упрощённая картина:

```text
Python list
+----------+----------+----------+
| ссылка A | ссылка B | ссылка C |
+----------+----------+----------+
     |          |          |
     v          v          v
    10       "hello"    словарь
```

Поэтому утверждение «массив хранит только один тип» верно для классического типизированного массива, но требует пояснения применительно к Python `list`.

## А что в JavaScript

JavaScript `Array` тоже позволяет смешивать типы:

```javascript
const items = [10, "hello", { active: true }];
```

Это высокоуровневая динамическая коллекция. Движки JavaScript используют внутренние оптимизации и могут хранить плотные однородные массивы эффективнее смешанных или разреженных.

Для алгоритмов важно не внутреннее устройство конкретной версии движка, а ожидаемое поведение операций:

- доступ по индексу обычно быстрый;
- добавление в конец обычно быстрое;
- вставка или удаление в начале/середине требует сдвигов либо иной дорогой внутренней работы.

## Где увидеть настоящий типизированный массив

### Python

```python
from array import array

numbers = array("q", [10, 20, 30])  # знаковые целые числа
```

Также типизированные плотные массивы используются в NumPy.

### JavaScript

```javascript
const numbers = new Int32Array([10, 20, 30]);
```

`Int32Array` хранит 32-битные целые числа и ближе к классическому представлению из лекции.

## Почему доступ по индексу O(1)

Если известны:

- адрес начала массива;
- размер одного элемента;
- нужный индекс,

адрес нужной ячейки вычисляется примерно так:

```text
адрес = начало + индекс × размер_элемента
```

Не нужно идти от первого элемента к нужному. Поэтому доступ `items[index]` имеет сложность `O(1)`.

```python
items = [5, 10, 15, 20]
print(items[2])  # 15
```

В Python это получение ссылки по индексу, после чего интерпретатор работает с самим объектом.

## size и capacity

Эти два понятия легко перепутать:

- `size` (длина) — сколько элементов сейчас находится в коллекции;
- `capacity` (ёмкость) — сколько элементов помещается в уже выделенную область без расширения.

Пример:

```text
size = 3
capacity = 6

[10] [20] [30] [пусто] [пусто] [пусто]
```

В Python `len(items)` показывает длину, но ёмкость напрямую обычным свойством не предоставляется. Она является внутренней деталью реализации.

## Сложность основных операций

Для динамического массива:

| Операция | Python | Обычная сложность | Почему |
|---|---|---:|---|
| Получить по индексу | `items[i]` | `O(1)` | Адрес ячейки вычисляется напрямую |
| Изменить по индексу | `items[i] = x` | `O(1)` | Известна нужная ячейка |
| Добавить в конец | `items.append(x)` | амортизированно `O(1)` | Обычно есть свободная ёмкость |
| Удалить последний | `items.pop()` | `O(1)` | Остальные элементы не сдвигаются |
| Вставить в начало/середину | `items.insert(i, x)` | `O(n)` | Элементы справа нужно сдвинуть |
| Удалить по индексу | `items.pop(i)` | `O(n)` | Элементы справа нужно сдвинуть |
| Найти значение | `x in items` | `O(n)` | Может потребоваться полный проход |

Амортизированная сложность `append` подробно разбирается в части 2.

## Почему вставка в середину O(n)

Было:

```text
индекс:  0    1    2    3
        [10] [20] [30] [40]
```

Вставляем `25` на индекс 2. Чтобы сохранить порядок, `30` и `40` нужно передвинуть вправо:

```text
индекс:  0    1    2    3    4
        [10] [20] [25] [30] [40]
```

Чем ближе вставка к началу и чем больше массив, тем больше элементов придётся сдвинуть.

## Почему удаление из середины O(n)

После удаления не должна оставаться дырка, иначе правило `items[i]` перестанет соответствовать ожидаемому расположению элементов. Элементы справа сдвигаются влево.

```python
items = [10, 20, 30, 40]
items.pop(1)

print(items)  # [10, 30, 40]
```

Если часто нужно удалять элементы с начала очереди, список — не лучший выбор:

```python
from collections import deque

queue = deque([10, 20, 30])
first = queue.popleft()  # O(1)
```

## Когда массив подходит хорошо

Массив или список особенно удобен, если:

- важен порядок;
- часто нужен доступ по индексу;
- элементы в основном добавляются в конец;
- коллекцию часто последовательно перебирают;
- вставки и удаления в начале или середине редки.

Примеры: результаты API, строки таблицы, история измерений, список товаров на странице, кадры анимации.

## Когда стоит подумать о другой структуре

- частый поиск по ключу — `dict`;
- частая проверка наличия — `set`;
- очередь с удалением слева — `collections.deque`;
- множество чисел с плотным хранением и вычислениями — NumPy;
- данные постоянно вставляются в произвольные места — возможно, нужна другая организация данных, но выбор зависит от задачи.

## Подход «два указателя»

Указатель в этой теме — обычно просто целочисленный индекс, а не низкоуровневый указатель из C++.

Используются две переменные, которые обозначают две позиции в массиве:

```python
left = 0
right = len(items) - 1
```

Затем один или оба индекса двигаются по определённому правилу.

Этот подход часто позволяет заменить вложенные циклы `O(n²)` одним проходом `O(n)`.

## Задача: два числа с заданной суммой

Дан **отсортированный** список. Нужно найти два числа, сумма которых равна `target`.

```python
def two_sum_sorted(numbers, target):
    left = 0
    right = len(numbers) - 1

    while left < right:
        current_sum = numbers[left] + numbers[right]

        if current_sum == target:
            return numbers[left], numbers[right]

        if current_sum < target:
            left += 1
        else:
            right -= 1

    return None
```

Почему это работает:

- если сумма слишком маленькая, нужно увеличить меньший элемент — двигаем `left` вправо;
- если сумма слишком большая, нужно уменьшить больший элемент — двигаем `right` влево;
- список отсортирован, поэтому движение предсказуемо меняет сумму.

Сложность:

- время — `O(n)`;
- дополнительная память — `O(1)`.

Без условия сортировки этот алгоритм использовать нельзя.

### Практический вариант для неотсортированного списка

Если исходный порядок не отсортирован и нужны индексы, можно использовать словарь:

```python
def two_sum(numbers, target):
    seen = {}

    for index, number in enumerate(numbers):
        missing = target - number

        if missing in seen:
            return seen[missing], index

        seen[number] = index

    return None
```

- время в среднем — `O(n)`;
- дополнительная память — `O(n)`.

Это хороший пример компромисса: тратим дополнительную память, чтобы сократить время.

## Задача: разворот на месте

Нужно развернуть список, не создавая второй список:

```python
def reverse_in_place(items):
    left = 0
    right = len(items) - 1

    while left < right:
        items[left], items[right] = items[right], items[left]
        left += 1
        right -= 1
```

Пример:

```text
[1, 2, 3, 4, 5]
 ^           ^      меняем 1 и 5

[5, 2, 3, 4, 1]
    ^     ^         меняем 2 и 4

[5, 4, 3, 2, 1]
```

- время — `O(n)`;
- дополнительная память — `O(1)`.

В рабочем Python-коде обычно достаточно `items.reverse()`. Ручной алгоритм нужен, чтобы понять технику двух указателей и изменение на месте.

## Изменение на месте и создание копии

```python
items.reverse()           # изменяет исходный список
copy = items[::-1]        # создаёт новый список
copy = list(reversed(items))
```

Эти варианты дают похожий видимый результат, но имеют разные последствия:

- изменение на месте может повлиять на другие участки кода, которые используют тот же список;
- копия требует `O(n)` дополнительной памяти, зато исходный список остаётся прежним.

## Что важно запомнить

1. Классический массив и Python `list` — не одно и то же, но `list` построен на идее динамического массива.
2. Разные типы в Python-списке возможны, потому что внутренний массив хранит ссылки.
3. Доступ по индексу — `O(1)`, вставка и удаление в середине — `O(n)`.
4. Два указателя часто превращают вложенный перебор в один линейный проход.
5. Для двух указателей важно понимать условие задачи, особенно наличие сортировки.
