# Самопроверка к лекции 3.1

## Вопросы

1. Какую задачу решает хеш-функция внутри таблицы?
2. Почему одинаковый хеш не означает одинаковые ключи?
3. Какова средняя и худшая сложность поиска?
4. Чем метод цепочек отличается от открытой адресации?
5. Почему при открытой адресации нельзя просто очистить удалённую ячейку?
6. Что показывает `load factor`?
7. Почему Python `list` нельзя использовать как ключ `dict`?
8. Какие ошибки допускает фильтр Блума?

## Выбери структуру

1. Получить пользователя по `id`.
2. Сохранить последовательность событий с повторами.
3. Быстро проверить уникальность email.
4. Найти все значения ключей из диапазона после сортировки.
5. Посчитать количество каждого слова.

Возможные ответы: `dict`, `list`, `set`, отсортированный список с границами, `Counter`/`dict`.

## Практика 1: первый повтор

```python
def first_duplicate(items):
    seen = set()

    for item in items:
        if item in seen:
            return item
        seen.add(item)

    return None
```

- среднее время — `O(n)`;
- дополнительная память — `O(n)`.

## Практика 2: пересечение

```python
def intersection(first, second):
    second_set = set(second)
    return [item for item in first if item in second_set]
```

Подумай, что произойдёт с дубликатами из `first`: они сохранятся. Если нужен набор уникальных общих значений, достаточно:

```python
result = set(first) & set(second)
```

## Практика 3: сгруппировать анаграммы

```python
def group_anagrams(words):
    groups = {}

    for word in words:
        key = tuple(sorted(word))
        groups.setdefault(key, []).append(word)

    return list(groups.values())
```

Слова с одинаковым отсортированным набором символов получают один ключ.

## Ответы

1. Преобразует произвольный хешируемый ключ в значение, по которому выбирается место хранения и путь поиска.
2. Диапазон хешей/индексов ограничен, поэтому разные ключи могут столкнуться; после хеша нужно проверить равенство ключа.
3. В среднем `O(1)`, в худшем случае `O(n)`.
4. Цепочки хранят несколько элементов при одной основной ячейке, открытая адресация ищет другую ячейку того же массива.
5. Она может разорвать путь к ключам, которые были размещены дальше из-за коллизии; нужна метка удаления.
6. Долю заполнения таблицы — отношение числа элементов к ёмкости.
7. Список изменяем и не имеет стабильного хеша для использования как ключ.
8. Может ошибочно сказать «возможно есть» для отсутствующего элемента, но без удаления не говорит «точно нет» для добавленного элемента.
