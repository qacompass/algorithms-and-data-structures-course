# 3.1. Хеш-таблицы

## Самая короткая версия

Хеш-таблица хранит пары **ключ — значение** и в среднем позволяет за `O(1)`:

- добавить пару;
- получить значение по ключу;
- проверить наличие ключа;
- удалить ключ.

В Python основные встроенные хеш-таблицы:

- `dict` — ключи и значения;
- `set` — только уникальные ключи.

В JavaScript похожие структуры:

- `Map`;
- `Set`;
- обычный объект тоже используется как словарь строковых/символьных ключей, но имеет другие правила и не является полной заменой `Map`.

## Зачем нужна хеш-таблица

Список пользователей:

```python
users = [
    {"id": 101, "name": "Анна"},
    {"id": 205, "name": "Илья"},
]
```

Поиск по `id` требует прохода `O(n)`.

Словарь:

```python
users_by_id = {
    101: {"id": 101, "name": "Анна"},
    205: {"id": 205, "name": "Илья"},
}

user = users_by_id.get(205)
```

Среднее время получения — `O(1)`.

## Что делает хеш-функция

Хеш-функция превращает ключ в целое хеш-значение. Из него реализация определяет позицию в таблице.

Упрощённо:

```text
ключ -> hash(key) -> индекс таблицы -> пара (ключ, значение)
```

Пример учебной идеи:

```python
index = hash(key) % capacity
```

Реальные реализации используют более сложные вычисления, но принцип тот же.

## Требования к хеш-функции

### Детерминированность внутри таблицы

Пока ключ находится в таблице, повторное хеширование должно приводить к тому же пути поиска.

### Хорошее распределение

Разные реальные ключи желательно равномерно распределять по таблице. Если все попадают в несколько ячеек, операции замедлятся.

### Быстрое вычисление

Если хеш вычисляется слишком долго, преимущество быстрого доступа исчезнет.

### Контракт равенства

Если два ключа равны, их хеши обязаны быть равны:

```text
a == b  =>  hash(a) == hash(b)
```

Обратное неверно: одинаковый хеш не означает равенство ключей.

## Почему ключи Python dict должны быть хешируемыми

```python
mapping = {
    "name": "Анна",
    42: "answer",
    (10, 20): "point",
}
```

Строки, числа и кортежи из хешируемых объектов обычно подходят.

```python
mapping[[10, 20]] = "point"  # TypeError
```

Список изменяем. Если изменить ключ после вставки, его хеш и логическое место могли бы поменяться, а таблица больше не смогла бы его найти.

Пользовательский объект тоже может быть ключом, если его `__eq__` и `__hash__` соблюдают контракт и значимые для хеша поля не меняются во время хранения.

## Хеш не является уникальным идентификатором

Количество возможных ключей огромно, а диапазон индексов таблицы ограничен. Поэтому разные ключи неизбежно иногда дают один и тот же индекс или хеш.

Это называется **коллизией**.

```text
hash("tap") -> 5
hash("pat") -> 5
```

Таблица обязана хранить исходный ключ и проверять равенство, а не доверять только хешу.

## Метод цепочек

Каждая ячейка хранит коллекцию всех пар, попавших в этот индекс:

```text
0 -> пусто
1 -> ("bread", 40) -> ("breadsticks", 63)
2 -> ("milk", 80)
```

При поиске:

1. вычисляется индекс;
2. просматривается цепочка;
3. ключи сравниваются на равенство.

Плюсы:

- понятная реализация;
- удаление относительно простое;
- таблица может хранить больше элементов, чем основных ячеек.

Минусы:

- дополнительная память на узлы или вложенные коллекции;
- плохая локальность памяти;
- длинные цепочки превращают поиск в `O(n)`.

## Открытая адресация

Все пары находятся прямо в массиве таблицы. При занятой позиции проверяются другие позиции по определённой последовательности.

### Линейное пробирование

```text
index, index + 1, index + 2, ...
```

Формула:

```text
(hash(key) + attempt) % capacity
```

Плюсы:

- данные находятся в одном массиве;
- хорошая локальность памяти;
- нет отдельного узла для каждой пары.

Минусы:

- образуются длинные кластеры занятых ячеек;
- производительность резко падает при высокой заполненности;
- удаление требует специального состояния.

## Почему при удалении нужен tombstone

Пусть два ключа столкнулись:

```text
index 5: key A
index 6: key B  # ушёл сюда из-за коллизии в 5
```

Если удалить `A` и сделать ячейку 5 полностью пустой, поиск `B` остановится на 5 и ошибочно решит, что `B` отсутствует.

Поэтому записывают специальную метку `REMOVED`:

```text
index 5: REMOVED
index 6: key B
```

- при поиске через `REMOVED` нужно идти дальше;
- при вставке такую ячейку можно переиспользовать;
- настоящая пустая ячейка означает, что цепочка поиска закончилась.

## Двойное хеширование

Чтобы уменьшить первичную кластеризацию, шаг пробирования получают второй хеш-функцией:

```text
index = (hash1(key) + attempt * hash2(key)) % capacity
```

Важно, чтобы шаг позволял обойти таблицу, а не зацикливался на небольшой части ячеек. Для этого размер таблицы и возможные шаги выбирают согласованно.

## Коэффициент заполнения load factor

```text
load_factor = number_of_items / capacity
```

Чем таблица плотнее, тем больше коллизий и пробирований. При достижении внутреннего порога реализация обычно:

1. выделяет более крупную таблицу;
2. заново распределяет элементы;
3. освобождает старую таблицу.

Эта операция стоит `O(n)`, но происходит редко. Поэтому вставка остаётся амортизированно `O(1)`.

## Почему операции «O(1)» только в среднем

При хорошем распределении проверяется небольшое постоянное число ячеек.

В худшем случае множество ключей сталкиваются, и приходится сравнивать много элементов. Тогда операция может деградировать до `O(n)`.

Корректная формулировка:

- среднее/амортизированное время основных операций — `O(1)`;
- худший случай — `O(n)`.

## Миниатюрная учебная таблица с цепочками

```python
class HashTable:
    def __init__(self, capacity=8):
        self.buckets = [[] for _ in range(capacity)]

    def _bucket(self, key):
        index = hash(key) % len(self.buckets)
        return self.buckets[index]

    def set(self, key, value):
        bucket = self._bucket(key)

        for pair in bucket:
            if pair[0] == key:
                pair[1] = value
                return

        bucket.append([key, value])

    def get(self, key, default=None):
        bucket = self._bucket(key)

        for stored_key, value in bucket:
            if stored_key == key:
                return value

        return default

    def delete(self, key):
        bucket = self._bucket(key)

        for index, pair in enumerate(bucket):
            if pair[0] == key:
                bucket.pop(index)
                return True

        return False
```

В этой модели нет автоматического расширения, подсчёта элементов и полноценного интерфейса. Она нужна только для демонстрации коллизий.

## Практические шаблоны с dict и set

### Частоты

```python
def frequencies(items):
    counts = {}

    for item in items:
        counts[item] = counts.get(item, 0) + 1

    return counts
```

```python
from collections import Counter

counts = Counter(items)
```

### Удаление дубликатов с сохранением порядка

```python
unique = list(dict.fromkeys(items))
```

### Поиск двух чисел с заданной суммой

```python
def two_sum(numbers, target):
    seen = {}

    for index, number in enumerate(numbers):
        missing = target - number

        if missing in seen:
            return seen[missing], index

        seen[number] = index

    return None
```

В среднем время `O(n)`, дополнительная память `O(n)`.

### Группировка

```python
groups = {}

for user in users:
    groups.setdefault(user.department, []).append(user)
```

## dict против list

| Требование | Обычно подходит |
|---|---|
| Доступ по целочисленной позиции | `list` |
| Доступ по произвольному ключу | `dict` |
| Уникальность и проверка наличия | `set` |
| Сохранение повторов и порядка | `list` |
| Диапазонный поиск по отсортированным данным | список + бинарный поиск |

Хеш-таблица не поддерживает полезный числовой порядок ключей для бинарного поиска или запроса «все ключи от 10 до 20». Для диапазонных задач нужны другие структуры или сортировка.

## JavaScript Map и Object

```javascript
const usersById = new Map();

usersById.set(101, { name: "Анна" });
usersById.set(205, { name: "Илья" });

const user = usersById.get(205);
const exists = usersById.has(101);
usersById.delete(101);
```

`Map`:

- принимает ключи любых типов;
- имеет явные методы `get`, `set`, `has`, `delete`;
- удобно итерируется;
- не смешивает пользовательские ключи с прототипом объекта.

Для простых записей с заранее известными строковыми полями объект остаётся естественным выбором:

```javascript
const user = { name: "Анна", age: 30 };
```

## Фильтр Блума

Фильтр Блума — компактная вероятностная структура для ответа на вопрос:

```text
"Этот элемент, возможно, присутствует?"
```

Используются:

- битовый массив;
- несколько хеш-функций.

При добавлении элемента несколько битов устанавливаются в `1`.

При проверке:

- если хотя бы один нужный бит равен `0`, элемента **точно нет**;
- если все биты равны `1`, элемент **возможно есть**.

## Ложноположительные ответы

Несколько других элементов могли случайно установить те же биты. Поэтому фильтр может сказать «возможно есть», когда элемента нет.

При обычной реализации без удаления:

- ложноположительные ответы возможны;
- ложноотрицательные ответы невозможны.

Фильтр Блума не возвращает само значение. Он помогает избежать дорогого запроса, когда заранее понятно, что результата точно нет.

## Где применяется фильтр Блума

- не обращаться к медленному диску или сети за точно отсутствующим ключом;
- фильтровать запросы к базе данных;
- проверять, встречался ли объект, с допустимой вероятностью ошибки;
- уменьшать число дорогих поисков в распределённых системах.

Чем больше элементов и чем меньше битов, тем выше вероятность ложноположительного ответа.

## Хеширование паролей — отдельная тема

Обычный `hash()` или быстрая хеш-функция таблицы **не подходят для хранения паролей**.

Пароли сохраняют с помощью специальных медленных алгоритмов формирования ключа с уникальной солью, например Argon2id, scrypt, bcrypt или PBKDF2 — выбор зависит от платформы и актуальных рекомендаций.

Хеш-таблица может использоваться для поиска записи пользователя, но безопасность пароля обеспечивает не структура `dict`, а специализированное парольное хеширование.

## Хеш-таблица и криптографический хеш — не одно и то же

- хеш таблицы оптимизирован для быстрого распределения ключей;
- криптографический хеш проектируется с требованиями стойкости;
- парольный хеш специально замедлен и использует соль;
- одинаковое слово «хеш» не делает эти инструменты взаимозаменяемыми.

## Где хеш-таблицы встречаются на практике

- словари конфигурации;
- индексы объектов по `id`;
- кеши;
- подсчёт частот;
- дедупликация;
- сопоставление маршрутов и обработчиков;
- таблицы символов компилятора;
- соединение наборов данных по ключу;
- мемоизация результатов функций.

## Что важно запомнить

1. `dict` и `set` основаны на хеш-таблицах.
2. Основные операции работают за `O(1)` в среднем, но не гарантированно в худшем случае.
3. Коллизии неизбежны и должны корректно разрешаться.
4. Цепочки и открытая адресация — два основных подхода.
5. При открытой адресации удаление требует метки `REMOVED`.
6. Рост таблицы поддерживает разумный коэффициент заполнения.
7. Фильтр Блума может дать ложноположительный, но не ложноотрицательный ответ без удаления.
8. Обычный хеш таблицы нельзя использовать вместо парольного хеширования.
