# Самопроверка к занятию 3.3

## Вопросы

1. Сколько возможных начальных позиций имеет шаблон длины `m` в тексте длины `n`?
2. Почему худшая сложность прямого перебора равна `O(n*m)`?
3. С какой стороны Хорспул начинает сравнивать шаблон?
4. Что хранит таблица смещений?
5. Почему Рабин — Карп не может вернуть совпадение только на основании равенства хешей?
6. Какие три действия нужны для обновления скользящего хеша?
7. Когда Рабин — Карп особенно удобен?

## Проследи прямой поиск

```python
text = "abababa"
pattern = "aba"
```

Возможные стартовые позиции: `0, 1, 2, 3, 4`.

Полные совпадения находятся на позициях:

```python
[0, 2, 4]
```

Они пересекаются, поэтому после совпадения для поиска всех результатов нужно сдвигаться на одну позицию, а не сразу на длину шаблона.

## Построй таблицу Хорспула

Для шаблона:

```text
"cocoa"
```

длина равна 5. Обрабатываем индексы от 0 до 3:

| Индекс | Символ | Смещение `4 - index` |
|---:|---|---:|
| 0 | `c` | 4 |
| 1 | `o` | 3 |
| 2 | `c` | 2 |
| 3 | `o` | 1 |

Поздние значения заменяют ранние:

```python
{"c": 2, "o": 1}
```

Для `a` и любых прочих отсутствующих в таблице символов используется значение по умолчанию `5`.

## Практика 1. Проверка реализации

Все три алгоритма должны пройти одинаковые тесты:

```python
test_cases = [

for text, pattern, expected in test_cases:

```

## Практика 2. Найти повторяющиеся фрагменты

Подумай, почему скользящий хеш удобен для поиска одинаковых окон фиксированной длины:

```python
def duplicate_windows(text, window_size):
    if window_size <= 0:
        raise ValueError("window_size must be positive")

    seen = set()
    duplicates = set()

    for start in range(len(text) - window_size + 1):
        window = text[start:start + window_size]

        if window in seen:
            duplicates.add(window)
        else:
            seen.add(window)

    return duplicates
```

Эта простая версия хранит сами подстроки. В больших задачах можно сначала хранить хеши, но при совпадении всё равно нужно учитывать возможность коллизии.

## Ответы

1. `n - m + 1`, если `m <= n`.
2. На каждой из `O(n)` позиций может потребоваться сравнить `O(m)` символов.
3. С последнего символа шаблона.
4. Безопасное расстояние, на которое можно сдвинуть шаблон после несовпадения.
5. Разные строки могут иметь одинаковый хеш — это коллизия.
6. Убрать вклад левого символа, умножить остаток на основание и добавить новый правый символ.
7. При поиске множества шаблонов одинаковой длины, повторяющихся окон или множества вхождений.
