# 3.3. Поиск подстроки в тексте

## Что решаем

Даны:

- `text` — строка, в которой ищем;
- `pattern` — подстрока или шаблон.

Нужно найти индекс первого вхождения:

```python
text = "hello algorithms"
pattern = "algo"

# результат: 6
```

Если шаблон отсутствует, обычно возвращают `-1`.

В реальных библиотеках соглашения могут отличаться, поэтому интерфейс функции нужно определить заранее:

- первое вхождение или все;
- разрешены ли пересекающиеся вхождения;
- что вернуть для пустого шаблона;
- учитывать ли регистр;
- искать символы Unicode или байты.

В конспекте используем соглашение Python `str.find()`:

- индекс первого вхождения;
- `-1`, если совпадения нет;
- пустой шаблон найден на позиции `0`.

## Что использовать в рабочем Python

Для обычной задачи не нужно вручную писать алгоритм:

```python
index = text.find(pattern)
exists = pattern in text
```

Ручные реализации нужны для понимания алгоритмов, специальных ограничений, поиска множества шаблонов или среды без подходящей библиотечной операции.

# Прямой перебор

## Идея

Выравниваем шаблон с каждой возможной начальной позицией текста и сравниваем символы слева направо.

```text
text:     e x a m p l e
pattern:  e x a

text:     e x a m p l e
pattern:    e x a

text:     e x a m p l e
pattern:      e x a
```

Если длина текста `n`, а шаблона `m`, возможны позиции от `0` до `n - m` включительно.

## Реализация первого вхождения

```python
def brute_force_search(text, pattern):
    if pattern == "":
        return 0
    if len(pattern) > len(text):
        return -1

    last_start = len(text) - len(pattern)

    for start in range(last_start + 1):
        matched = True

        for offset in range(len(pattern)):
            if text[start + offset] != pattern[offset]:
                matched = False
                break

        if matched:
            return start

    return -1
```

Короткая учебная версия со срезом:

```python
def brute_force_search_with_slices(text, pattern):
    for start in range(len(text) - len(pattern) + 1):
        if text[start:start + len(pattern)] == pattern:
            return start

    return 0 if pattern == "" else -1
```

Срез создаёт новую строку, поэтому скрывает дополнительную работу и память. Для объяснения посимвольного алгоритма первая версия точнее.

## Все вхождения, включая пересекающиеся

```python
def find_all_brute_force(text, pattern):
    if pattern == "":
        return list(range(len(text) + 1))

    result = []
    last_start = len(text) - len(pattern)

    for start in range(last_start + 1):
        for offset, character in enumerate(pattern):
            if text[start + offset] != character:
                break
        else:
            result.append(start)

    return result
```

```python
find_all_brute_force("aaaa", "aa")  # [0, 1, 2]
```

`else` относится к циклу `for`: он выполняется, если цикл закончился без `break`.

## Сложность прямого перебора

В худшем случае для каждой позиции сравнивается почти весь шаблон:

```text
text    = "aaaaaaaaab"
pattern = "aaaab"
```

- время — `O((n - m + 1) * m)`, обычно упрощают до `O(n * m)`;
- дополнительная память посимвольной версии — `O(1)`.

На случайных данных несовпадение часто находится быстро, поэтому фактическое время может быть заметно лучше худшей оценки.

# Алгоритм Бойера — Мура — Хорспула

## Главная идея

Прямой перебор всегда сдвигает шаблон на одну позицию. Алгоритм Хорспула использует информацию о символах шаблона, чтобы иногда перескочить сразу через несколько заведомо бесполезных позиций.

Сравнение начинается **с конца шаблона**.

```text
text:       ... s w e e t ...
pattern:        s w e e t
                         ^ начинаем справа
```

При несовпадении смотрим на символ текста, выровненный с последним символом шаблона, и берём заранее вычисленный сдвиг.

## Таблица смещений

Для шаблона `"sweet"`, длина которого равна 5:

```text
символ:    s  w  e  t  прочие
смещение:  4  3  1  5     5
```

Последний символ шаблона при обычном построении таблицы пропускается. Для каждого символа до него записывается расстояние до конца:

```python
def build_shift_table(pattern):
    pattern_length = len(pattern)
    shifts = {}

    for index in range(pattern_length - 1):
        shifts[pattern[index]] = pattern_length - 1 - index

    return shifts
```

Если символ повторяется, более поздняя запись заменяет раннюю. В таблице остаётся вхождение, ближайшее к концу шаблона, а значит — минимальный безопасный сдвиг.

Символ, которого в таблице нет, получает сдвиг `len(pattern)`.

## Реализация Хорспула

```python
def horspool_search(text, pattern):
    if pattern == "":
        return 0

    text_length = len(text)
    pattern_length = len(pattern)

    if pattern_length > text_length:
        return -1

    shifts = build_shift_table(pattern)
    start = 0

    while start <= text_length - pattern_length:
        pattern_index = pattern_length - 1

        while (
            pattern_index >= 0
            and pattern[pattern_index]
            == text[start + pattern_index]
        ):
            pattern_index -= 1

        if pattern_index < 0:
            return start

        aligned_character = text[start + pattern_length - 1]
        start += shifts.get(aligned_character, pattern_length)

    return -1
```

## Почему берётся последний выровненный символ

В версии Хорспула решение о сдвиге всегда принимается по символу текста, который сейчас находится под последним символом шаблона. Это упрощение полного алгоритма Бойера — Мура.

Нельзя сдвигать шаблон произвольно далеко: можно перескочить через настоящее совпадение. Таблица хранит расстояние, при котором ближайшее подходящее вхождение символа в шаблоне выровняется с текстом.

## Сложность Хорспула

- подготовка таблицы — `O(m)` времени и до `O(m)` памяти;
- на многих практических текстах алгоритм пропускает позиции и работает близко к линейному времени;
- лучший сценарий может выполнять примерно `O(n / m)` проверок выравниваний;
- худший случай остаётся `O(n * m)`.

Алгоритм особенно полезен, когда:

- алфавит достаточно большой;
- шаблон не слишком короткий;
- символы текста и шаблона часто различаются;
- выполняется поиск одного шаблона.

Для шаблона длины 1 преимущества больших сдвигов исчезают.

# Алгоритм Рабина — Карпа

## Главная идея

Вместо полного сравнения шаблона с каждым окном сначала сравниваются их хеши.

```text
pattern -> hash

text[0:m] -> hash
text[1:m+1] -> hash
text[2:m+2] -> hash
...
```

Если хеши различаются, строки точно различаются. Если хеши совпали, нужно выполнить точное сравнение, потому что возможна коллизия.

## Почему нельзя доверять только хешу

Разные строки могут иметь одинаковое хеш-значение:

```text
hash(window) == hash(pattern)
```

не гарантирует:

```text
window == pattern
```

Поэтому корректный алгоритм использует хеш как быстрый фильтр, а не как окончательное доказательство равенства.

## Полиномиальный хеш

Строку можно представить как многочлен из кодов символов:

```text
code(s₀) * base^(m-1)
+ code(s₁) * base^(m-2)
+ ...
+ code(sₘ₋₁)
```

Чтобы числа не росли бесконечно, результат берут по модулю простого числа.

```python
BASE = 257
MODULUS = 1_000_000_007
```

Конкретные константы — часть инженерного выбора. Они не устраняют коллизии полностью.

## Схема Горнера

Наивное вычисление многочлена многократно возводит `base` в степень. Схема Горнера переписывает его так:

```text
(((a₀ * base + a₁) * base + a₂) * base + ...)
```

```python
def polynomial_hash(text, base=257, modulus=1_000_000_007):
    result = 0

    for character in text:
        result = (result * base + ord(character)) % modulus

    return result
```

Хеш строки длины `m` вычисляется за `O(m)`.

## Скользящий хеш

Пересчитывать хеш каждого окна с нуля означало бы снова получить `O(n * m)`. Скользящий хеш обновляет значение за `O(1)`:

1. вычитает вклад уходящего левого символа;
2. умножает остаток на `base`;
3. добавляет новый правый символ;
4. берёт результат по модулю.

```text
старое окно: [a b c]
новое окно:    [b c d]
```

## Реализация Рабина — Карпа

```python
def rabin_karp_search(
    text,
    pattern,
    base=257,
    modulus=1_000_000_007,
):
    if pattern == "":
        return 0

    text_length = len(text)
    pattern_length = len(pattern)

    if pattern_length > text_length:
        return -1

    highest_power = pow(base, pattern_length - 1, modulus)
    pattern_hash = 0
    window_hash = 0

    for index in range(pattern_length):
        pattern_hash = (
            pattern_hash * base + ord(pattern[index])
        ) % modulus
        window_hash = (
            window_hash * base + ord(text[index])
        ) % modulus

    last_start = text_length - pattern_length

    for start in range(last_start + 1):
        if (
            window_hash == pattern_hash
            and text.startswith(pattern, start)
        ):
            return start

        if start == last_start:
            break

        outgoing = ord(text[start]) * highest_power
        incoming = ord(text[start + pattern_length])

        window_hash = (
            (window_hash - outgoing) * base + incoming
        ) % modulus

    return -1
```

`text.startswith(pattern, start)` проверяет точное совпадение без создания среза.

## Пошаговый смысл формулы обновления

Для окна длины 3:

```text
hash("abc") = a*b² + b*b + c
```

Убираем вклад `a*b²`:

```text
b*b + c
```

Умножаем на основание:

```text
b*b² + c*b
```

Добавляем новый символ `d`:

```text
b*b² + c*b + d = hash("bcd")
```

В формулах `b` здесь обозначает основание; символы условно представлены их числовыми кодами.

## Все вхождения через Рабина — Карпа

После совпадения не обязательно завершать функцию. Можно добавить `start` в список и продолжить сдвиги. Так находятся и пересекающиеся совпадения.

```python
def rabin_karp_all(text, pattern):
    if pattern == "":
        return list(range(len(text) + 1))

    result = []
    start = 0

    while start <= len(text) - len(pattern):
        found = rabin_karp_search(text[start:], pattern)

        if found == -1:
            break

        absolute_index = start + found
        result.append(absolute_index)
        start = absolute_index + 1

    return result
```

Эта короткая обёртка повторно запускает поиск и создаёт срезы, поэтому она не является оптимальной реализацией всех вхождений. Для производительного варианта нужно продолжать один проход и сохранять найденные позиции.

## Сложность Рабина — Карпа

При хорошем распределении хеша:

- подготовка хеша шаблона и первого окна — `O(m)`;
- проход по тексту — `O(n)`;
- среднее время — `O(n + m)`;
- дополнительная память — `O(1)` для одного шаблона и фиксированного числа хешей.

В худшем случае много окон дают тот же хеш и каждое приходится сравнивать целиком:

- худшее время — `O(n * m)`.

При поиске множества шаблонов одинаковой длины Рабин — Карп особенно удобен: хеши шаблонов можно сохранить в множестве и проверять каждое окно текста сразу против всей группы.

## Сравнение трёх подходов

| Алгоритм | Подготовка | Средняя идея | Худший случай | Доп. память |
|---|---:|---|---:|---:|
| Прямой перебор | нет | проверяем каждую позицию | `O(n*m)` | `O(1)` |
| Хорспул | `O(m)` | пропускаем невозможные позиции | `O(n*m)` | `O(m)` |
| Рабин — Карп | `O(m)` | сравниваем скользящие хеши | `O(n*m)` | `O(1)` для одного поиска |

Асимптотический худший случай у всех трёх может совпадать, но реальное поведение и подходящие сценарии различаются.

## Когда какой алгоритм понятнее

### Прямой перебор

- маленькие строки;
- простота важнее оптимизации;
- учебная отправная точка.

### Хорспул

- один шаблон;
- большой алфавит;
- достаточно длинный шаблон;
- ожидаются частые несовпадения.

### Рабин — Карп

- много шаблонов одинаковой длины;
- нужно найти много вхождений;
- удобно использовать скользящий хеш;
- допустима проверка кандидатов после совпадения хешей.

## Unicode и нормализация

Визуально одинаковый текст может иметь разные последовательности Unicode-кодов. Например, символ с диакритикой может быть записан одним кодом или буквой плюс отдельным комбинируемым знаком.

Если задача предполагает пользовательский текст, перед поиском иногда требуется нормализация:

```python
import unicodedata

normalized_text = unicodedata.normalize("NFC", text)
normalized_pattern = unicodedata.normalize("NFC", pattern)
```

Если нужно игнорировать регистр, можно применять `casefold()`. Но преобразования меняют индексы и длину в некоторых языках, поэтому требования к возвращаемой позиции нужно продумать отдельно.

## JavaScript

Для рабочего кода обычно достаточно:

```javascript
const index = text.indexOf(pattern);
const exists = text.includes(pattern);
```

Ручной алгоритм отличается только синтаксисом. При работе с Unicode важно помнить, что индекс строки JavaScript относится к UTF-16 code units, а не обязательно к видимым символам.

## Частые ошибки

1. Не обработать пустой шаблон.
2. Взять неправильную последнюю стартовую позицию и пропустить конец текста.
3. В Хорспуле неверно рассчитать расстояние до конца шаблона.
4. При повторяющемся символе сохранить не самое правое допустимое вхождение.
5. В Рабине — Карпе считать равные хеши доказательством равенства строк.
6. Пересчитывать хеш каждого окна с нуля и потерять преимущество алгоритма.
7. Забыть взять остаток по модулю после обновления.
8. Не определить, нужны ли пересекающиеся совпадения.

## Что важно запомнить

1. Прямой поиск сравнивает шаблон на каждой возможной позиции.
2. Хорспул начинает сравнение справа и использует таблицу безопасных сдвигов.
3. Рабин — Карп обновляет хеш окна за `O(1)`.
4. Совпадение хешей всегда нужно подтверждать сравнением строк.
5. Среднее время Рабина — Карпа — `O(n + m)`, худшее — `O(n*m)`.
6. В рабочем коде сначала следует рассмотреть встроенные `find`, `in`, `indexOf` и `includes`.
