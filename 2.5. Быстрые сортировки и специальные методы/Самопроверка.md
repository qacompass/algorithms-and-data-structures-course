# Самопроверка к лекции 2.5

## Вопросы

1. Из каких трёх шагов состоит «разделяй и властвуй»?
2. Почему merge sort имеет `O(n log n)`?
3. Что делает слияние устойчивым?
4. Когда quick sort деградирует до `O(n²)`?
5. Чем Quickselect отличается от полной сортировки?
6. Что означает `k` в сложности counting sort `O(n + k)`?
7. Почему проходы radix sort должны быть устойчивыми?

## Выбери алгоритм

1. Нужно гарантированное `O(n log n)` и важна устойчивость.
2. Миллион оценок от 1 до 5.
3. Нужно найти медиану, полная сортировка не требуется.
4. Нужно отсортировать произвольные объекты библиотечным способом.

Возможные ответы: merge sort; counting sort; Quickselect; встроенная сортировка.

## Проследи слияние

Слей вручную:

```python
left = [2, 5, 9]
right = [1, 3, 10]
```

Сравниваются пары `2/1`, `2/3`, `5/3`, `5/10`, `9/10`, после чего добавляется остаток. Результат: `[1, 2, 3, 5, 9, 10]`.

## Практика

Модифицируй counting sort так, чтобы она возвращала частоты, а не отсортированный массив:

```python
def frequencies(numbers):
    result = {}

    for number in numbers:
        result[number] = result.get(number, 0) + 1

    return result
```

Словарь удобнее массива счётчиков, если диапазон огромный, но реально встречается мало значений. При этом для получения отсортированного результата ключи словаря всё равно придётся упорядочить.

## Ответы

1. Разделить, решить части, объединить результаты.
2. Есть `O(log n)` уровней деления, на каждом обрабатывается `O(n)` элементов.
3. При равных ключах сначала брать элемент из левой половины.
4. Когда pivot систематически создаёт крайне несбалансированные части.
5. Он продолжает только в части, содержащей нужный индекс, и не упорядочивает все остальные элементы.
6. Размер диапазона возможных значений ключа.
7. Иначе сортировка по новому разряду разрушит порядок, полученный на предыдущих разрядах.
