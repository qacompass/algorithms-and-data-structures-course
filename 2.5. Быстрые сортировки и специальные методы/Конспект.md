# 2.5. Продвинутые сортировки

## Почему нужны другие алгоритмы

`O(n²)` быстро становится непрактичным:

- 1 000 элементов — порядка миллиона сравнений;
- 100 000 элементов — порядка десяти миллиардов.

Сортировки с типичной сложностью `O(n log n)` масштабируются значительно лучше.

## Разделяй и властвуй

Общий принцип:

1. разделить задачу на меньшие части;
2. решить каждую часть;
3. объединить частичные решения.

Так работают сортировка слиянием и быстрая сортировка, но объединяют результаты они по-разному.

# Сортировка слиянием

## Идея

1. Делим массив пополам, пока не останутся одноэлементные части.
2. Один элемент уже отсортирован.
3. Сливаем соседние отсортированные части двумя указателями.

```text
[11, 5, 2, 9]
       |
[11, 5] [2, 9]
   |       |
[11] [5] [2] [9]
   |       |
[5, 11] [2, 9]
       |
[2, 5, 9, 11]
```

## Реализация

```python
def merge(left, right):
    result = []
    left_index = 0
    right_index = 0

    while left_index < len(left) and right_index < len(right):
        if left[left_index] <= right[right_index]:
            result.append(left[left_index])
            left_index += 1
        else:
            result.append(right[right_index])
            right_index += 1

    result.extend(left[left_index:])
    result.extend(right[right_index:])
    return result


def merge_sort(items):
    if len(items) < 2:
        return items.copy()

    middle = len(items) // 2
    left = merge_sort(items[:middle])
    right = merge_sort(items[middle:])
    return merge(left, right)
```

Использование `<=` при равных элементах выбирает элемент из левой части первым и сохраняет устойчивость.

## Сложность merge sort

- уровней деления — `O(log n)`;
- на каждом уровне все `n` элементов участвуют в слиянии;
- итоговое время — `O(n log n)` во всех случаях;
- дополнительная память — `O(n)`;
- алгоритм устойчив.

Merge sort подходит для внешней сортировки больших файлов и параллельной обработки: части можно сортировать независимо.

# Быстрая сортировка

## Идея

1. Выбираем опорный элемент `pivot`.
2. Разделяем элементы на меньшие, равные и большие.
3. Рекурсивно сортируем меньшую и большую части.

Простая учебная реализация:

```python
def quick_sort(items):
    if len(items) < 2:
        return items.copy()

    pivot = items[len(items) // 2]
    lower = [item for item in items if item < pivot]
    equal = [item for item in items if item == pivot]
    higher = [item for item in items if item > pivot]

    return quick_sort(lower) + equal + quick_sort(higher)
```

Эта версия понятна, но не является in-place и создаёт дополнительные списки.

## Почему выбор pivot важен

Если части примерно равны:

```text
n -> n/2 + n/2
```

получаем `O(n log n)`.

Если каждый раз одна часть почти пустая:

```text
n -> 0 + (n-1) -> 0 + (n-2) ...
```

получаем `O(n²)` и глубокую рекурсию.

Стратегии:

- случайный pivot;
- медиана из трёх элементов;
- качественное разбиение с обработкой дубликатов.

Нельзя утверждать, что худший случай «невозможен»: он реален для неудачного выбора pivot или специально подобранных данных.

## Свойства quick sort

- среднее время — `O(n log n)`;
- худшее — `O(n²)`;
- классические in-place варианты используют небольшой объём памяти для перестановок, но стек рекурсии остаётся;
- обычная in-place реализация неустойчива;
- часто хорошо работает на массивах благодаря локальности памяти.

# K-я порядковая статистика

Нужно найти элемент, который оказался бы на позиции `k` в отсортированном массиве, но полностью сортировать всё необязательно.

Например, медиана — одна из порядковых статистик.

Алгоритм Quickselect:

1. выполняет разбиение как quick sort;
2. определяет, в какой части находится индекс `k`;
3. продолжает только в этой части.

Простая версия:

```python
def quickselect(items, k):
    if not 0 <= k < len(items):
        raise IndexError("k is out of range")

    pivot = items[len(items) // 2]
    lower = [item for item in items if item < pivot]
    equal = [item for item in items if item == pivot]
    higher = [item for item in items if item > pivot]

    if k < len(lower):
        return quickselect(lower, k)
    if k < len(lower) + len(equal):
        return pivot

    return quickselect(
        higher,
        k - len(lower) - len(equal),
    )
```

- среднее время — `O(n)`;
- худшее при неудачных разбиениях — `O(n²)`;
- здесь `k` — индекс с нуля.

Если нужен один минимум, Quickselect не нужен: достаточно `min()` за `O(n)`.

# Сортировка подсчётом

## Когда сравнения не нужны

Если ключи — целые числа из небольшого известного диапазона, можно посчитать количество каждого значения.

```python
def counting_sort(numbers):
    if not numbers:
        return []

    minimum = min(numbers)
    maximum = max(numbers)
    counts = [0] * (maximum - minimum + 1)

    for number in numbers:
        counts[number - minimum] += 1

    result = []

    for offset, count in enumerate(counts):
        result.extend([offset + minimum] * count)

    return result
```

Если `n` — число элементов, а `k` — размер диапазона:

- время — `O(n + k)`;
- память — `O(k)`.

## Когда counting sort плох

```text
[1, 1_000_000_000]
```

Элементов всего два, но массив счётчиков потребовал бы миллиард ячеек. Алгоритм выгоден только при разумном диапазоне ключей.

Простое восстановление чисел устойчивостью не обладает как объектная сортировка. Устойчивый counting sort строят через накопленные количества и отдельный выходной массив.

# Поразрядная сортировка

Radix sort обрабатывает ключ по частям — например, по десятичным разрядам справа налево.

```text
153, 266, 323

сначала единицы,
затем десятки,
затем сотни.
```

Сортировка каждого разряда должна быть устойчивой, иначе порядок, созданный предыдущим разрядом, разрушится.

Если:

- `d` — число разрядов;
- `n` — число элементов;
- `b` — размер алфавита разряда,

сложность обычно записывают `O(d * (n + b))`.

Radix sort применим, когда ключ можно представить как фиксированное или ограниченное число перечислимых фрагментов: целые числа, байты, иногда строки определённого формата.

## Почему существует граница O(n log n)

Для сортировок, основанных только на попарных сравнениях произвольных ключей, в общем случае нельзя гарантировать асимптотику лучше `O(n log n)`.

Counting sort и radix sort обходят это ограничение, потому что используют дополнительные свойства ключей: ограниченный диапазон или структуру разрядов.

## Сравнение

| Алгоритм | Среднее время | Худшее | Память | Устойчивость |
|---|---:|---:|---:|---|
| Merge sort | `O(n log n)` | `O(n log n)` | `O(n)` | да |
| Quick sort | `O(n log n)` | `O(n²)` | зависит от реализации | обычно нет |
| Quickselect | `O(n)` | `O(n²)` | зависит от реализации | не сортировка |
| Counting sort | `O(n + k)` | `O(n + k)` | `O(k)` | возможна |
| Radix sort | `O(d(n+b))` | зависит от разрядов | дополнительная | требует стабильных проходов |

## Что делает Python

В приложении используй:

```python
ordered = sorted(items, key=...)
```

Python предоставляет устойчивую оптимизированную сортировку. Ручной quick sort или merge sort нужны для обучения, специальных ограничений либо реализации алгоритма в среде без подходящей библиотеки.

Для нескольких наименьших или наибольших элементов полезен `heapq`:

```python
import heapq

smallest_three = heapq.nsmallest(3, numbers)
```

## Что важно запомнить

1. Merge sort всегда работает за `O(n log n)`, устойчива, но требует `O(n)` памяти.
2. Quick sort в среднем быстра, но может деградировать до `O(n²)`.
3. Quickselect не сортирует всё и находит одну позицию в среднем за `O(n)`.
4. Counting sort выгодна только при небольшом диапазоне ключей.
5. Radix sort требует устойчивой обработки каждого разряда.
6. Линейные сортировки быстрее сравнительных только благодаря ограничениям на ключи.
