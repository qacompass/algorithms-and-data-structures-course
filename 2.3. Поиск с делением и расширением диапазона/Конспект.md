# 2.3. Тернарный и экспоненциальный поиск

## Что объединяет эти алгоритмы

Оба поиска используют упорядоченность, но делают это по-разному:

- тернарный поиск делит текущий диапазон на три части;
- экспоненциальный поиск сначала быстро находит примерный диапазон, а затем запускает бинарный поиск.

## Тернарный поиск в отсортированном массиве

Вместо одной середины вычисляются две:

```python
third = (right - left) // 3
middle_left = left + third
middle_right = right - third
```

Диапазон делится на три части:

```text
[ left ... middle_left ... middle_right ... right ]
```

После сравнений остаётся одна из трёх частей.

```python
def ternary_search(items, target):
    left = 0
    right = len(items) - 1

    while left <= right:
        third = (right - left) // 3
        middle_left = left + third
        middle_right = right - third

        if items[middle_left] == target:
            return middle_left
        if items[middle_right] == target:
            return middle_right

        if target < items[middle_left]:
            right = middle_left - 1
        elif target > items[middle_right]:
            left = middle_right + 1
        else:
            left = middle_left + 1
            right = middle_right - 1

    return -1
```

## Тернарный против бинарного

Тернарный поиск выполняет `O(log₃ n)` итераций, бинарный — `O(log₂ n)`. В Big O оба являются `O(log n)`, потому что основание логарифма отличается только постоянным множителем.

При этом тернарному поиску обычно требуется больше сравнений на итерацию. Поэтому для поиска значения в обычном отсортированном массиве бинарный поиск чаще проще и быстрее.

Тернарный поиск действительно часто применяют в другой постановке: для поиска минимума или максимума унимодальной функции — функции, которая сначала монотонно растёт, а затем убывает, или наоборот. Но в этой лекции рассматривается поиск по отсортированной последовательности.

## Экспоненциальный поиск

Представим отсортированный массив, но мы не знаем, насколько далеко находится `target`. Начинаем с маленькой границы и удваиваем её:

```text
1 -> 2 -> 4 -> 8 -> 16 -> 32 ...
```

Как только значение на границе стало не меньше `target`, получен диапазон для бинарного поиска.

```python
from bisect import bisect_left


def exponential_search(items, target):
    if not items:
        return -1

    if items[0] == target:
        return 0

    border = 1

    while border < len(items) and items[border] < target:
        border *= 2

    left = border // 2
    right = min(border + 1, len(items))
    index = bisect_left(items, target, left, right)

    if index < len(items) and items[index] == target:
        return index

    return -1
```

`bisect_left` принимает полуоткрытый диапазон `[left, right)`, поэтому правая граница передаётся как `border + 1`.

## Ручная комбинация с бинарным поиском

```python
def binary_search_range(items, target, left, right):
    while left <= right:
        middle = left + (right - left) // 2

        if items[middle] == target:
            return middle
        if items[middle] < target:
            left = middle + 1
        else:
            right = middle - 1

    return -1


def exponential_search_manual(items, target):
    if not items:
        return -1
    if items[0] == target:
        return 0

    border = 1

    while border < len(items) and items[border] < target:
        border *= 2

    return binary_search_range(
        items,
        target,
        border // 2,
        min(border, len(items) - 1),
    )
```

## Сложность экспоненциального поиска

Пусть искомый элемент находится около индекса `m`.

1. Удвоение границы займёт `O(log m)` шагов.
2. Бинарный поиск в найденном диапазоне тоже займёт `O(log m)`.

Итого — `O(log m)`, а не обязательно `O(log n)`.

Это полезно, если элемент находится близко к началу очень большой последовательности.

## Когда экспоненциальный поиск полезен

- размер отсортированного источника заранее неизвестен;
- доступ к данным предоставляется как к условно бесконечной последовательности;
- искомый элемент часто находится близко к началу;
- сначала нужно найти разумную верхнюю границу для бинарного поиска по ответу.

Для обычного Python `list`, длина которого известна через `len()`, стандартный бинарный поиск обычно проще.

## Поиск только результирующего отрезка

Иногда задача требует не найти значение, а вернуть диапазон, где оно может находиться:

```python
def exponential_range(items, target):
    if not items:
        return None

    border = 1

    while border < len(items) and items[border] < target:
        border *= 2

    return border // 2, min(border, len(items) - 1)
```

После этого другой алгоритм может обработать только найденный участок.

## Связь с бинарным поиском по ответу

Когда неизвестна верхняя граница ответа:

```python
right = 1

while not predicate(right):
    right *= 2
```

Экспоненциальное расширение находит подходящую правую границу. Затем бинарный поиск находит первый допустимый ответ.

Это распространённая комбинация, а не два конкурирующих алгоритма.

## Частые ошибки

1. Применить оба алгоритма к неотсортированным данным.
2. Не ограничить `border` длиной массива.
3. Перепутать включительную и невключительную правую границу.
4. Считать тернарный поиск асимптотически быстрее бинарного: оба `O(log n)`.
5. Забыть отдельно проверить пустой массив и первый элемент.

## Что важно запомнить

1. Тернарный поиск делит диапазон на три части, но для обычного массива редко выигрывает у бинарного.
2. Основание логарифма не меняет класс Big O.
3. Экспоненциальный поиск находит диапазон удвоением границы.
4. После уточнения диапазона используется бинарный поиск.
5. Сложность экспоненциального поиска зависит от позиции `m`: `O(log m)`.
