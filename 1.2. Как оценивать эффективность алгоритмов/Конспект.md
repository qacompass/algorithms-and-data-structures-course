# 1.2. Сложность алгоритмов

## Самая короткая версия

Сложность показывает, **как растёт объём работы алгоритма при увеличении количества входных данных**.

Big O не отвечает на вопрос «сколько миллисекунд работает программа». Он помогает понять, что произойдёт с алгоритмом, если данных станет в 10, 100 или 1000 раз больше.

## Почему нельзя просто измерить секунды

Время зависит от компьютера, версии Python, нагрузки, сети и множества других факторов. Один и тот же алгоритм на двух компьютерах даст разные миллисекунды, но характер роста останется одинаковым.

Например, если для каждого элемента мы выполняем одно простое действие, при удвоении количества элементов работы станет примерно вдвое больше. Это линейный рост — `O(n)`.

`n` обычно означает количество элементов во входных данных.

## Основные сложности

| Сложность | Простое объяснение | Пример |
|---|---|---|
| `O(1)` | Количество работы почти не зависит от размера коллекции | Получить элемент списка по индексу |
| `O(log n)` | На каждом шаге область поиска сильно уменьшается | Бинарный поиск |
| `O(n)` | Нужно один раз пройти по данным | Найти максимум в неотсортированном списке |
| `O(n log n)` | Типичная сложность эффективной сортировки | `sorted()` в общем случае |
| `O(n²)` | Для каждого элемента просматриваем много других элементов | Два вложенных прохода по одному списку |
| `O(2ⁿ)` | Число вариантов очень быстро удваивается | Наивная рекурсия Фибоначчи |
| `O(n!)` | Нужно перебрать все перестановки | Полный перебор маршрутов |

## O(1): постоянная сложность

```python
def first(items):
    return items[0]
```

Неважно, 10 элементов в списке или миллион: для получения элемента по известному индексу не требуется просматривать предыдущие элементы.

`O(1)` не означает «ровно одна машинная операция». Это означает, что объём работы не растёт вместе с `n`.

## O(n): линейная сложность

```python
def contains(items, target):
    for item in items:
        if item == target:
            return True

    return False
```

В худшем случае нужно проверить каждый элемент. Если список стал в десять раз длиннее, проверок может стать примерно в десять раз больше.

## Почему O(3n) превращается в O(n)

```python
for item in items:
    do_first(item)

for item in items:
    do_second(item)

for item in items:
    do_third(item)
```

Здесь три прохода: примерно `3n` действий. В Big O постоянный множитель отбрасывают, потому что нас интересует характер роста. И `n`, и `3n` растут линейно.

Это не значит, что три прохода равны одному по реальному времени. Big O — грубая модель роста, а не точный секундомер.

## O(n²): квадратичная сложность

```python
def all_pairs(items):
    for first in items:
        for second in items:
            print(first, second)
```

Если элементов `n`, внутренний цикл выполняется примерно `n` раз для каждого из `n` элементов: получается `n × n`.

При 10 элементах получится около 100 пар, при 1000 — около миллиона.

### Два разных входных размера

```python
for user in users:
    for order in orders:
        ...
```

Корректнее записать `O(u × o)`, где `u` — число пользователей, а `o` — число заказов. Не всегда нужно называть это `O(n²)`, потому что коллекции могут иметь совершенно разные размеры.

## Последовательные и вложенные циклы

Это важное различие:

```python
# O(n): два последовательных прохода дают O(n + n) = O(n)
for item in items:
    ...

for item in items:
    ...
```

```python
# O(n²): один проход вложен в другой
for first in items:
    for second in items:
        ...
```

## Берём наиболее быстро растущую часть

Если алгоритм выполняет `n² + n + 100` условных действий, для большого `n` часть `n²` начинает доминировать. Поэтому сложность записывают как `O(n²)`.

## Рекурсивные числа Фибоначчи

Наивный вариант:

```python
def fib(n):
    if n <= 1:
        return n

    return fib(n - 1) + fib(n - 2)
```

Функция многократно вычисляет одни и те же значения. Например, `fib(3)` будет рассчитан в нескольких ветках. Количество вызовов растёт примерно экспоненциально — `O(2ⁿ)`.

Итерационный вариант:

```python
def fib(n):
    if n <= 1:
        return n

    previous = 0
    current = 1

    for _ in range(2, n + 1):
        previous, current = current, previous + current

    return current
```

- время: `O(n)`;
- дополнительная память: `O(1)`.

Обе функции дают одинаковый результат, но используют совершенно разное количество ресурсов.

## Бинарный поиск и O(log n)

Если данные отсортированы, можно сравнить искомое значение со средним элементом и отбросить сразу половину вариантов.

```python
def binary_search(items, target):
    left = 0
    right = len(items) - 1

    while left <= right:
        middle = (left + right) // 2

        if items[middle] == target:
            return middle
        if items[middle] < target:
            left = middle + 1
        else:
            right = middle - 1

    return -1
```

Для миллиона отсортированных элементов потребуется около 20 шагов, а не миллион. Но есть обязательное условие: коллекция должна быть отсортирована.

На практике в Python обычно используют готовый модуль `bisect`, но ручная реализация помогает понять принцип.

## Пузырьковая сортировка

Пузырьковая сортировка сравнивает соседние элементы и меняет их местами. Для полной сортировки приходится многократно проходить по массиву, поэтому типичная и худшая сложность — `O(n²)`.

```python
def bubble_sort(items):
    items = items.copy()

    for right in range(len(items) - 1, 0, -1):
        swapped = False

        for index in range(right):
            if items[index] > items[index + 1]:
                items[index], items[index + 1] = items[index + 1], items[index]
                swapped = True

        if not swapped:
            break

    return items
```

В рабочем коде следует использовать `sorted(items)` или `items.sort()`. Пузырьковую сортировку изучают не как рекомендацию, а как наглядный пример вложенных проходов.

## Временная и пространственная сложность

Алгоритм может расходовать:

- **время** — количество выполняемой работы;
- **память** — объём дополнительных данных.

Пример разворота с созданием нового списка:

```python
reversed_items = items[::-1]
```

Работа и дополнительная память растут вместе с количеством элементов: время `O(n)`, дополнительная память `O(n)`.

Если менять элементы исходного списка попарно, дополнительной памяти потребуется `O(1)`.

## Худший, лучший и средний случаи

При линейном поиске:

- лучший случай: нужное значение первое — `O(1)`;
- худший случай: значение последнее или отсутствует — `O(n)`;
- средний случай: потребуется проверить некоторую часть списка — всё равно линейный характер роста.

Когда без уточнения говорят Big O алгоритма, чаще всего имеют в виду верхнюю оценку, нередко для худшего случая.

В лекции также упоминаются:

- `Ω` (омега) — нижняя граница;
- `Θ` (тета) — точная асимптотическая граница, когда сверху и снизу рост одного порядка.

На первом этапе важнее научиться уверенно распознавать основные классы Big O.

## Особенность примера с setTimeout из лекции

В JavaScript `setTimeout` планирует выполнение функции на будущее. Цикл сначала быстро создаёт таймеры, а обработчики выполняются позднее через очередь событий.

```javascript
const items = [36, 18, 9];

for (let i = 0; i < items.length; i += 1) {
  setTimeout(() => console.log(items[i]), items[i]);
}
```

Задержки влияют на порядок появления результатов, но ожидание таймера не является обычной вычислительной работой цикла. Здесь нельзя просто посмотреть на миллисекунды задержки и назвать их алгоритмической сложностью.

## Где это применяется

- понять, выдержит ли обработка рост данных;
- заметить лишние вложенные циклы;
- выбрать между списком, словарём и множеством;
- сравнить два корректных решения;
- объяснить медленный участок до запуска профилировщика;
- оценить стоимость сортировки, поиска и копирования.

## Что важно запомнить

1. Big O описывает рост, а не точное время.
2. Последовательные проходы складываются, вложенные — обычно перемножаются.
3. Константы и медленно растущие части отбрасываются в итоговой записи.
4. У алгоритма есть сложность по времени и по дополнительной памяти.
5. Оптимизировать нужно осмысленно: сначала выбрать хороший алгоритм, затем измерять реальную программу.
