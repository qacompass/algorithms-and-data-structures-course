# 2.1. Бинарный поиск

## Самая короткая версия

Бинарный поиск ищет значение в **отсортированной** последовательности, каждый раз отбрасывая половину оставшегося диапазона.

- линейный поиск — `O(n)`;
- бинарный поиск — `O(log n)`;
- обязательное условие бинарного поиска — данные упорядочены по тому же ключу, который используется при сравнении.

## Линейный поиск

```python
def linear_search(items, target):
    for index, item in enumerate(items):
        if item == target:
            return index

    return -1
```

Он подходит, когда:

- данные не отсортированы;
- коллекция маленькая;
- поиск выполняется один раз и сортировать дороже;
- данные можно читать только последовательно.

В худшем случае проверяются все `n` элементов: время `O(n)`, дополнительная память `O(1)`.

## Идея бинарного поиска

Для массива:

```text
[1, 3, 4, 7, 8, 9, 11, 12, 16, 21, 36]
```

ищем `7`:

1. Берём середину.
2. Если середина равна `7`, ответ найден.
3. Если середина меньше `7`, левая половина больше не нужна.
4. Если середина больше `7`, правая половина больше не нужна.
5. Повторяем для оставшегося диапазона.

Так работает игра «Угадай число», когда после попытки сообщают «больше» или «меньше».

## Итеративная реализация

```python
def binary_search(items, target):
    left = 0
    right = len(items) - 1

    while left <= right:
        middle = left + (right - left) // 2
        value = items[middle]

        if value == target:
            return middle
        if value < target:
            left = middle + 1
        else:
            right = middle - 1

    return -1
```

### Что означают границы

Здесь используется **закрытый интервал** `[left, right]`: оба индекса входят в область поиска.

Поэтому:

- начальный `right = len(items) - 1`;
- цикл работает при `left <= right`;
- после проверки середины она исключается через `middle + 1` или `middle - 1`.

Смешивание разных схем границ — главная причина ошибок в бинарном поиске.

## Почему middle считают так

```python
middle = left + (right - left) // 2
```

В Python вариант `(left + right) // 2` безопасен: целые числа не переполняются. Но в языках с целыми фиксированного размера сумма больших индексов может переполниться. Универсальная формула сразу формирует хорошую привычку.

В JavaScript для обычных массивов переполнение индексов практически не является проблемой, но формула остаётся ясной и переносимой.

## Почему сложность O(log n)

Размер диапазона уменьшается вдвое:

```text
64 -> 32 -> 16 -> 8 -> 4 -> 2 -> 1
```

Для 64 элементов нужно не больше примерно 6 делений. Для миллиона — около 20.

Число делений `n` пополам до единицы равно примерно `log₂(n)`. Основание логарифма в Big O не указывают, потому что смена основания даёт постоянный множитель.

## Рекурсивный вариант

```python
def binary_search_recursive(items, target, left=0, right=None):
    if right is None:
        right = len(items) - 1

    if left > right:
        return -1

    middle = left + (right - left) // 2

    if items[middle] == target:
        return middle
    if items[middle] < target:
        return binary_search_recursive(
            items, target, middle + 1, right
        )

    return binary_search_recursive(
        items, target, left, middle - 1
    )
```

Время остаётся `O(log n)`, но стек рекурсии занимает `O(log n)`. Итеративная версия требует `O(1)` дополнительной памяти и обычно предпочтительнее.

## Когда сортировка окупается

Если неотсортированный набор используется один раз:

- линейный поиск — `O(n)`;
- сортировка плюс бинарный поиск — `O(n log n) + O(log n)`.

Сортировать ради одного поиска бессмысленно.

Если данные сортируются один раз, а затем выполняется много поисков, первоначальная цена сортировки может окупиться.

Ещё один вариант — построить `set` или `dict` за `O(n)` и выполнять проверки наличия в среднем за `O(1)`. Выбор зависит от требований:

- нужен порядок или поиск ближайшей границы — сортировка и бинарный поиск;
- нужна только проверка наличия — часто удобнее множество;
- важно сохранить исходный порядок — сортировка создаёт дополнительные последствия.

## Дубликаты: обычного поиска недостаточно

```text
[1, 3, 3, 3, 3, 7]
```

Обычный бинарный поиск может вернуть любой индекс со значением `3`. Если нужен первый или последний, алгоритм меняют.

## Левая граница: первое вхождение

Ищем первый индекс, где значение **не меньше** `target` (`lower bound`).

```python
def lower_bound(items, target):
    left = 0
    right = len(items)

    while left < right:
        middle = left + (right - left) // 2

        if items[middle] < target:
            left = middle + 1
        else:
            right = middle

    return left
```

Здесь используется полуоткрытый интервал `[left, right)`. `right` может быть равен `len(items)` и обозначать позицию после последнего элемента.

Первое точное вхождение:

```python
def first_occurrence(items, target):
    index = lower_bound(items, target)

    if index < len(items) and items[index] == target:
        return index

    return -1
```

## Правая граница: позиция после последнего вхождения

Ищем первый индекс, где значение **строго больше** `target` (`upper bound`).

```python
def upper_bound(items, target):
    left = 0
    right = len(items)

    while left < right:
        middle = left + (right - left) // 2

        if items[middle] <= target:
            left = middle + 1
        else:
            right = middle

    return left
```

Последнее точное вхождение находится на позиции `upper_bound(...) - 1`, если там действительно лежит `target`.

```python
def last_occurrence(items, target):
    index = upper_bound(items, target) - 1

    if index >= 0 and items[index] == target:
        return index

    return -1
```

## Сколько раз встречается значение

```python
def count_occurrences(items, target):
    return upper_bound(items, target) - lower_bound(items, target)
```

Обе границы находятся за `O(log n)`. Не нужно проходить все дубликаты.

## Готовый Python bisect

В рабочем Python-коде обычно используют стандартную библиотеку:

```python
from bisect import bisect_left, bisect_right

left = bisect_left(items, target)
right = bisect_right(items, target)
count = right - left
```

Ручная реализация нужна для понимания и для задач, где критерий отличается от обычного сравнения элементов.

## JavaScript

В стандартном JavaScript отдельной встроенной функции бинарного поиска нет:

```javascript
function binarySearch(items, target) {
  let left = 0;
  let right = items.length - 1;

  while (left <= right) {
    const middle = left + Math.floor((right - left) / 2);
    const value = items[middle];

    if (value === target) return middle;
    if (value < target) left = middle + 1;
    else right = middle - 1;
  }

  return -1;
}
```

## Частые ошибки

1. Применить поиск к неотсортированным данным.
2. Использовать `left < right` там, где границы включительные и последний элемент ещё нужно проверить.
3. Не исключать уже проверенную середину и получить бесконечный цикл.
4. Возвращать первый найденный дубликат, когда нужен самый левый.
5. Не проверить пустой массив.
6. Перепутать индекс и само значение.

## Что важно запомнить

1. Бинарный поиск работает только при монотонном порядке.
2. На каждом шаге отбрасывается половина вариантов: `O(log n)`.
3. Нужно последовательно придерживаться одной схемы границ.
4. Обычный поиск не гарантирует первый или последний дубликат.
5. `lower_bound` и `upper_bound` являются универсальными шаблонами.
6. В Python для обычных задач есть модуль `bisect`.
