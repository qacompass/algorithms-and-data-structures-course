# 1.7. Разбор задач на очереди, списки, деки и стеки

## Зачем нужен этот урок

Здесь важны не новые структуры данных, а умение увидеть, что одну задачу можно решить несколькими способами. Решения могут быть одинаково правильными, но отличаться:

- количеством дополнительной памяти;
- простотой кода;
- удобством доказательства корректности;
- возможностью обработать крайние случаи.

В уроке разобраны три задачи:

1. является ли одна строка подпоследовательностью другой;
2. является ли строка палиндромом;
3. удаление узлов с заданным значением из односвязного списка.

## Задача 1. Является ли строка подпоследовательностью

Формулировка «в исходную строку добавили символы» означает следующее: можно ли получить строку `source`, удалив некоторые символы из `candidate`, но **не меняя порядок оставшихся**.

```text
source    = "abc"
candidate = "aXbYYc"
результат = True
```

`"abc"` встречается в правильном порядке.

```text
source    = "abc"
candidate = "acb"
результат = False
```

Все буквы есть, но порядок `b` и `c` изменён.

Это называется проверкой подпоследовательности (`subsequence`). Подстрока (`substring`) — другое понятие: её символы должны идти подряд.

### Решение через очередь

Можно положить символы `source` в очередь. Просматривая `candidate`, извлекаем первый ожидаемый символ, когда встречаем его.

```python
from collections import deque


def is_subsequence_queue(source, candidate):
    expected = deque(source)

    for character in candidate:
        if expected and character == expected[0]:
            expected.popleft()

    return not expected
```

Обязательна проверка `expected`: иначе обращение `expected[0]` к уже пустой очереди вызовет ошибку.

Сложность:

- время — `O(len(source) + len(candidate))`;
- дополнительная память — `O(len(source))`.

### Решение двумя указателями

Очередь здесь не обязательна. Индекс `source_index` может показывать следующий ожидаемый символ.

```python
def is_subsequence(source, candidate):
    source_index = 0

    for character in candidate:
        if (
            source_index < len(source)
            and source[source_index] == character
        ):
            source_index += 1

    return source_index == len(source)
```

Логика:

- по `candidate` всегда идём вперёд;
- индекс в `source` двигаем только при совпадении;
- если дошли до конца `source`, все его символы найдены в правильном порядке.

Сложность:

- время — `O(len(candidate))`;
- дополнительная память — `O(1)`.

Это предпочтительный вариант: он короче и не копирует строку в очередь.

### Важные крайние случаи

```python
assert is_subsequence("", "anything") is True
assert is_subsequence("abc", "") is False
assert is_subsequence("abc", "abc") is True
assert is_subsequence("aaa", "aa") is False
assert is_subsequence("ace", "abcde") is True
```

Пустая строка является подпоследовательностью любой строки: для неё уже найдено ноль необходимых символов.

### JavaScript

```javascript
function isSubsequence(source, candidate) {
  let sourceIndex = 0;

  for (const character of candidate) {
    if (
      sourceIndex < source.length &&
      source[sourceIndex] === character
    ) {
      sourceIndex += 1;
    }
  }

  return sourceIndex === source.length;
}
```

Алгоритм не изменился — поменялся только синтаксис.

## Задача 2. Палиндром

Палиндром одинаково читается слева направо и справа налево:

```text
"level" -> True
"abba"  -> True
"python" -> False
```

Перед решением реальной задачи нужно уточнить правила:

- учитывать ли регистр;
- игнорировать ли пробелы и знаки препинания;
- допускается ли пустая строка;
- работаем только со словом или с целой фразой.

### Решение через стек

Стек возвращает символы в обратном порядке:

```python
def is_palindrome_stack(text):
    stack = list(text)

    for character in text:
        if character != stack.pop():
            return False

    return True
```

- время — `O(n)`;
- дополнительная память — `O(n)`.

Решение наглядно показывает LIFO, но создаёт копию всех символов.

### Решение через дек

```python
from collections import deque


def is_palindrome_deque(text):
    characters = deque(text)

    while len(characters) > 1:
        if characters.popleft() != characters.pop():
            return False

    return True
```

Мы сравниваем крайние символы и удаляем их. Время `O(n)`, память `O(n)`.

### Решение двумя указателями

```python
def is_palindrome(text):
    left = 0
    right = len(text) - 1

    while left < right:
        if text[left] != text[right]:
            return False

        left += 1
        right -= 1

    return True
```

- время — `O(n)`;
- дополнительная память — `O(1)`.

Это наиболее экономный вариант. Мы не разворачиваем строку и не создаём коллекцию.

### Палиндром-фраза

```python
def is_phrase_palindrome(text):
    left = 0
    right = len(text) - 1

    while left < right:
        while left < right and not text[left].isalnum():
            left += 1

        while left < right and not text[right].isalnum():
            right -= 1

        if text[left].casefold() != text[right].casefold():
            return False

        left += 1
        right -= 1

    return True
```

Здесь указатели пропускают пробелы и пунктуацию, а `casefold()` приводит символы к форме для сравнения без учёта регистра.

## Задача 3. Удаление значений из связного списка

Нужно удалить **все** узлы, у которых `data == target`.

```text
1 -> 3 -> 3 -> 4 -> None, target = 3

1 -----------> 4 -> None
```

### Почему голова создаёт особый случай

Обычный узел удаляется переключением ссылки предыдущего узла:

```python
previous.next = current.next
```

Но перед `head` нет настоящего предыдущего узла. Можно написать отдельную обработку головы, но несколько совпадающих узлов в начале усложнят код.

### Фиктивный узел dummy

Создадим временный узел перед головой:

```text
dummy -> head -> ...
```

Теперь даже у старой головы есть предыдущий узел.

```python
class ListNode:
    def __init__(self, data=0, next_node=None):
        self.data = data
        self.next = next_node


def remove_elements(head, target):
    dummy = ListNode(next_node=head)
    previous = dummy
    current = head

    while current is not None:
        if current.data == target:
            previous.next = current.next
        else:
            previous = current

        current = current.next

    return dummy.next
```

Ключевая деталь: после удаления `previous` не двигается. Он должен остаться перед следующим узлом — тот тоже может оказаться удаляемым.

```text
previous -> [3] -> [3] -> [4]
              удалить первый 3

previous ------> [3] -> [4]
```

Если сразу передвинуть `previous`, второй узел можно пропустить.

Сложность:

- время — `O(n)`;
- дополнительная память — `O(1)`;
- создаётся один фиктивный узел, его количество не зависит от `n`.

### Крайние случаи

```text
remove_elements(None, 3)              # None
remove_elements(3 -> None, 3)         # None
remove_elements(3 -> 3 -> None, 3)    # None
remove_elements(1 -> 2 -> None, 3)    # список не изменится
```

Стрелочная запись здесь иллюстративная, не Python-синтаксис.

## Общий урок из трёх задач

### Не каждая подходящая структура обязательна

Подпоследовательность можно проверить очередью, а палиндром — стеком или деком. Но два указателя дают ту же временную сложность без дополнительной памяти.

### Dummy-узел убирает особый случай

Фиктивные узлы полезны, когда операция у головы или хвоста отличается от операции в середине. Они часто делают код короче и надёжнее.

### Сначала определяй инвариант

Инвариант — утверждение, которое остаётся истинным во время алгоритма:

- в подпоследовательности уже найден префикс `source[:source_index]`;
- в палиндроме всё за пределами `[left, right]` уже проверено;
- при удалении `previous.next` указывает на первый ещё не обработанный или сохранённый узел.

## Что важно запомнить

1. Подпоследовательность сохраняет порядок, но её символы не обязаны идти подряд.
2. Два указателя часто заменяют стек, очередь или дополнительную копию.
3. Палиндром проверяется за `O(n)` времени и `O(1)` памяти.
4. Dummy-узел позволяет удалять голову так же, как остальные узлы.
5. При удалении подряд идущих узлов нельзя безусловно двигать `previous`.
